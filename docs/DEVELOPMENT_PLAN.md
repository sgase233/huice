依赖顺序：E0 → E1 → E2；E3a 的纯展示可与 E1 并行，**本人轨迹不能提前放权**；E3b 的统计定义和埋点可提前设计，但全局查询上线依赖 E1，趋势展示依赖真实采集。E4 汇合全部能力。

## 6. 验收与留证

扩展用例见 [ACCEPTANCE 扩展矩阵](product/ACCEPTANCE.md#扩展验收矩阵2026-11-09新增待执行)。每项须记录实际环境、代码/契约/迁移版本、样本、预期、实际、证据、复测及签认。至少包括两个企业账号互相越权、一个审核员全局只读、同键重复提交、抓取失败/空更新、轮换与提交竞态、历史 run 与历史政策版本关联、跨北京时间日期边界统计、缺测与真实零的区别。
