# 华为 ICT 大赛创新赛赛题一：中小企业政策红利挖掘与申报多智能体初步策划案

> 修订稿｜2026 年 10 月 19 日｜项目暂名：**惠策协同**
>
> 本文依据工作区《评审建议_惠策协同方案_可行性与优化.md》修订，用于确定参赛作品的产品边界、技术路径和验证方法。评审建议中关于赛题“必选项”的判断，仍须以团队登录后取得的组委会原始赛题附件为最终依据；本文把 CodeArts、RDS、Redis 和 MaaS 列为拟实现路径，不把第三方转述当作最终规则。

## 1. 项目概述与参赛定位

**一句话概括：**企业填写一次基础画像，系统从可信政策来源发现潜在机会，逐条解释适用条件和缺失证据，并把可办理事项整理成申报准备任务；涉及税额与最终资格的判断交由企业财税人员复核。

第十一届华为 ICT 大赛（2026—2027）创新赛的**赛题一**为“基于华为云产品打造 AI 创新应用”，与团队所说的“赛道一”对应。高校发布的参赛通知显示，创新赛重视真实场景、AI 与 ICT 综合应用、技术架构和应用价值；初赛安排在 2026 年 12 月。作品按赛题一构建，同时呈现**应用效果**和**利用华为云完成开发、构建、修复与上线的过程**。赛题二的 AgentArts 和赛题三的 Nexent 是其他赛题的专门方向。[赛题设置与校赛通知](https://cs.bjut.edu.cn/info/1076/4323.htm) · [第十一届报名通知与赛程](https://chuangxin.dlut.edu.cn/info/1020/16867.htm)

**目标用户：**没有专职政策研究团队的中小企业负责人、财务人员和项目申报人员。首个试点选择**深圳市的科技或制造业中小企业**，覆盖国家级税收优惠与深圳市级公开资金申报通知。选择单一城市，是为了让政策层级、地域条件和申报入口可核实。全国复制列为后续阶段。

**核心价值：**把“发现机会—核对条件—收集证据—准备申报—持续跟踪”串为可追溯流程。工信部明确提出要加强惠企政策汇集解析和精准匹配、打通政策落地环节；这一需求已有公共服务基础，项目须以实际效率和判断质量证明增量价值。[工信部中小企业公共服务体系指导意见](https://wap.miit.gov.cn/jgsj/qyj/wjfb/art/2023/art_6ace4489268b4ce0a1aa0d8e8a01e3fa.html)

**边界：**产品是政策信息整理与材料准备工具，不承诺企业一定取得资助，也不代替纳税申报、电子签章、政府平台提交或财税专业判断。涉税页面和导出报告均显示“政策信息辅助整理；非税务专业意见；申报前请企业财税人员核对”的提示。“可申报金额”“预计节税额”只在规则、期间和企业数据均齐备时显示测算过程；否则显示“待核实”，不将不同性质的优惠简单相加。

## 2. 用户问题与需求优先级

| 工作环节 | 典型困难 | 产品应交付的结果 | 优先级 |
| --- | --- | --- | --- |
| 找政策 | 政策分布在部委、税务和地方部门网站；标题难以判断是否相关 | 根据地区、行业和企业画像形成候选清单，附原文链接与有效期 | P0 |
| 判资格 | 申报条件跨正文、附件和当期通知；部分信息企业尚未整理 | 输出“满足／不满足／证据不足／条款冲突”及逐条依据 | P0 |
| 算收益 | 财政补贴、税前扣除和税额减免口径不同 | 按政策类型分别给出测算依据或拒绝测算原因 | P1 |
| 备材料 | 材料名称与格式随项目变化，容易漏项 | 材料清单、截止时间、缺失证据提示 | P0 |
| 跟进变化 | 项目窗口关闭或条款修订后，旧结论可能失效 | 版本变化提示与重新核验任务 | P1 |

**必须区分两类流程：**财政资金项目通常有申报通知、材料和受理窗口；部分税收优惠属于企业自行判断、申报享受、资料留存备查。以研发费用加计扣除为例，税务机关说明其办理方式为“真实发生、自行判别、申报享受、相关资料留存备查”，不宜套用资金项目的“提交申请、等待拨款”流程。[国家税务总局研发费用政策执行说明](https://fgk.chinatax.gov.cn/zcfgk/c100018/c5213378/content.html)

## 3. 产品方案与典型体验

### 3.1 用户主流程

1. **建立画像：**企业选择所在地区、行业、成立时间、经营规模、是否有研发活动及项目投入情况。仅在确有必要时补充经营和财务指标；每个字段标记“用户填写／材料提取／尚未核实”。
2. **发现机会：**展示政策名称、类别、发文机关、适用地区、有效期、申报窗口、入口和初步相关性。优先显示官方原文，区分政策依据与解读文章。
3. **资格核验：**把政策条件拆成可执行规则。每条结论同时显示企业事实、证据出处和对应政策条款；不能判定时优先询问最有可能改变结论的一个事实，并说明为什么要问。
4. **形成行动卡：**资金项目生成静态材料清单、官方入口和截止时间；税收优惠生成核算与留存备查清单，并在界面提示财税人员复核。
5. **变更跟踪：**政策更新、窗口开启或关闭、企业画像变化时重新计算，并说明哪些结论发生变化。

### 3.2 演示案例（合成企业，不对应真实纳税人）

“鹏城智造”设为深圳注册的中小型软件与设备研发企业，用户提供地区、行业、季度人数与资产数据、研发项目和支出摘要。系统在候选清单中展示：

- **研发费用税前加计扣除：**核查行业排除条件、核算方式、研发活动和费用归集证据；展示可适用的政策口径及待确认项目。税务总局资料说明，符合条件的研发费用自 2023 年起可按实际发生额的 100% 加计扣除，形成无形资产的按成本 200% 税前摊销。演示仅输出规则解释，不据此直接计算企业最终应纳税额。[国家税务总局政策说明](https://www.chinatax.gov.cn/chinatax/c102419/c5204648/content.html)
- **小型微利企业所得税优惠：**核对年度应纳税所得额、从业人数、资产总额和行业条件。使用年度季度平均值规则，不以单个季度值替代全年判断；信息不足时标为“待核实”。现行税务说明将优惠执行期列至 2027 年底。[国家税务总局适用条件与办理方式](https://www.chinatax.gov.cn/chinatax/n810356/n3010387/c5211219/content.html)
- **深圳市级项目样例：**选取深圳市工信部门发布的“2026 年企业技术改造扶持计划传统优势产业数字化转型项目”通知作为**历史通知解析样本**，演示系统如何识别地区、项目条件、材料与申报窗口；不把历史通知展示为当前开放事项。实际申报以部门当期通知及附件为准。[深圳市政府原始通知](https://www.sz.gov.cn/cn/xxgk/zfxxgj/tzgg/content/post_12639379.html)

演示最后应形成一张可下载的“机会与行动报告”：每项政策包含结论、缺口、原文定位、版本时间和下一步准备事项。报告上区分“可以开始准备材料”和“已确认符合条件”；后者只有证据充分且人工核对完成时才可显示。

## 4. 多智能体设计

采用**一个协调器 + 四个专职智能体 + 独立的规则与引用校验器**。智能体负责采集、抽取、整理与解释；资格阈值、日期、比例和逻辑组合由确定性程序执行。职责分离的理由是各环节的工具、上下文、失败模式和复核点不同；是否优于单智能体，须通过第 7 节的消融实验验证。

| 角色 | 输入 | 输出 | 关键约束 |
| --- | --- | --- | --- |
| 政策采集智能体 | 官方站点白名单、政策页或附件 | 原文、发文信息、层级、地区、版本、申报窗口 | 来源与抓取时间必填；附件要关联正文 |
| 条款解析智能体 | 政策原文与附件 | 可执行条件表达式、材料、互斥条件、办理方式 | 每条规则绑定原文片段；引用校验不通过即退回 |
| 企业画像智能体 | 用户输入和授权上传的文件 | 标准化企业事实及证据链 | 不推断未提供的财务事实；敏感字段最小化 |
| 解释与准备智能体 | 规则引擎结果、材料要求、官方入口 | 条款级解释、分类型清单、报告草稿 | 只能解释已核验结果；不得生成虚假证明材料 |
| 协调器 | 用户请求、各环节状态 | 调度、重试、人工复核请求、审计轨迹 | 对过期政策、引用冲突和证据缺口实行拦截 |

**一次匹配的状态流：**`原文入库 → 条款抽取 → 引用校验 → 人工抽检 → 企业事实入库 → 规则求值 → 解释与清单 → 人工确认`。保留各步输入输出、政策版本和模型版本，形成可展示的审计轨迹。演示版不开发复杂任务状态流转。

### 4.1 核心技术：条件表达式与引用双通道

将 `Criterion` 设计为可解释的表达式树（AST），支持数值区间、比例、季度平均值、`AND/OR/NOT`、行业排除清单和日期条件。例如“小型微利企业”的人数条件应由四个季度平均值再计算全年平均值，不能只看最后一个季度。[国家税务总局适用条件与计算口径](https://www.chinatax.gov.cn/chinatax/n810356/n3010387/c5211219/content.html)

每条表达式存储 `source_url + policy_version + section/page + 原文片段`。大模型抽取后，**独立校验器**检查数字、单位、比较方向、适用期间和行业名称是否得到所引片段支持；仅有词面相同不足以通过，否定词和适用范围也须核对。校验失败进入人工复核，不发布可执行规则。第一版允许人工录入规则，优先保证准确性。

**四态判断：**“满足／不满足／证据不足／条款冲突”。先用地区、主体、行业、时间等硬条件排除，再检索与解释；事实缺失时不得判“满足”。附件与正文关系、政策废止或新旧版本冲突无法确定时，展示冲突来源并暂停结论。

**最少补充提问：**对尚未确定的条件，按“该事实可能改变多少候选政策结论、获取成本、敏感程度”评分，先问高收益且低负担的问题。MVP 实现贪心选择，不承诺全局最优；用固定顺序提问作对照，比较达到相同判断所需的问题数。

**结论时效性：**`Assessment` 除结果外，还存 `evaluated_at`、政策版本、企业事实哈希、所依赖事实的期间及 `valid_until`。政策条款或企业事实变化后，旧结论标记“依据已失效，待复核”，保留历史报告，不静默覆盖。

**最小数据模型：**`Policy`（标题、机关、地区、有效期、原文 URL、版本）；`Program`（事项类别、窗口、入口）；`Criterion`（AST、原文定位、校验状态）；`EnterpriseFact`（字段、值、期间、证据、核验状态）；`Assessment`（四态结果、原因、版本、事实哈希、结论有效期）；`Evidence`（文件名、页码或片段）。演示版材料清单由报告生成，不单独建设多人任务系统。

## 5. 技术实现与华为云使用

### 5.1 拟定技术栈与职责

| 层 | 本项目拟采用的华为云能力 | 具体用途与验收证据 |
| --- | --- | --- |
| 智能开发 | 华为云码道 CodeArts 代码智能体、Skills | 需求拆解、模块编码、故障修复与部署辅助；保留原始记录、提交与录屏。[产品文档](https://support.huaweicloud.com/productdesc-codeartsagent/codeartsagent_pd_0001.html) · [Skills 文档](https://support.huaweicloud.com/usermanual-codeartsagent/codeartsagent_ug_0024.html) |
| 应用运行 | 华为云 ECS 上的 Web 前端与 API | 提供可访问的可视化 Demo、健康检查和部署手册；计算规格由首周验证决定 |
| 结构化与向量数据 | RDS for PostgreSQL + pgvector | 存政策版本、表达式树、企业合成画像、判断记录及小规模向量索引；华为云文档确认 RDS PostgreSQL 支持 pgvector，但**实例版本须现场检查**。[pgvector 使用文档](https://support.huaweicloud.com/usermanual-rds-pg/rds_09_0062.html) |
| 缓存 | 华为云分布式缓存服务 Redis 版 | 缓存政策解析结果和版本化判断，避免重复调用模型；记录命中率与失效演示。[华为云 Skills 门户](https://skills.huaweicloud.com/) |
| 原文文件 | OBS | 保存官方政策 PDF、附件和合成演示材料；RDS 中只存对象引用与校验摘要 |
| 模型推理 | 华为云 MaaS API | 离线条款抽取、受限解释与文本向量化；记录 token、延时、失败率与费用。[MaaS 功能说明](https://support.huaweicloud.com/intl/zh-cn/productdesc-maas/productdesc_maas_0005.html) |

以 **RDS + pgvector** 支撑 MVP 的小规模混合检索，暂不引入 CSS；当政策量和检索性能实测超过单库能力时再评估 CSS。这样能将时间用于规则忠实度和评测。模型服务的**提供商、模型版本、地域和费率**须以账号控制台实测锁定；“优先某一模型”不是赛题要求。MaaS 的部分 API 与预置模型有地域限制，首周须验证部署地域、网络可达性和数据流向。[MaaS 快速入门](https://support.huaweicloud.com/intl/zh-cn/qs-maas/qs-maas-0001.html) · [MaaS V2 接口限制](https://support.huaweicloud.com/intl/zh-cn/model-call-maas/model-call-019.html)

**Redis 的实质用途：**判断缓存键采用 `assessment:{enterprise_id}:{policy_id}:{policy_version}:{fact_hash}`。政策版本或企业事实变化后生成新键，并将旧记录标记待复核；缓存设置到期时间，不能作为唯一持久化证据。政策解析缓存按原文哈希与解析器版本索引，避免重复消耗 MaaS token。

**推理成本：**条款抽取在政策入库阶段离线批处理，校验后落 RDS；现场演示优先复用已审核规则，只对用户提问和解释调用 MaaS。按每份政策的输入／输出 token 和重试次数估算预算，设置调用上限；超额或限流时展示已保存的可复核结果，而不伪装实时推理。

### 5.2 把开发过程作为作品证据

评审建议所附赛题文字强调呈现华为云产品在“需求理解、代码生成、项目构建、问题修复、部署上线”中的使用价值。团队从开工第一天维护 `docs/codearts-log.md`，逐项记录日期、任务、使用的智能体或 Skill、提示词摘要、产出、人工改动、提交号和实际耗时；敏感凭据不得进入日志或录屏。

| 环节 | 留存证据 | 答辩展示 |
| --- | --- | --- |
| 需求理解 | CodeArts 对话记录、生成的需求拆解、人工改动 | 原始记录与最终需求表对照 |
| 代码生成 | 生成模块、提示词版本、代码提交与人工重写内容 | 选一个核心模块展示差异 |
| 项目构建 | Skills 创建或配置 RDS、Redis 的调用与资源清单 | 30 秒录屏；如 Skills 不支持目标规格，如实展示手工配置步骤 |
| 问题修复 | 两个真实故障的报错、修复建议、测试结果与代码差异 | 一例成功、一例人工介入 |
| 部署上线 | 构建、配置、部署、访问和回滚步骤 | 云端 Demo 与可复现部署手册 |

开发效率只按真实任务日志汇总，比较“人工预估、CodeArts 辅助实际耗时、人工修改量”；不在策划阶段填造节省比例。赛题原始附件中的具体工具、材料和开源要求，由团队在取得官方版本后逐项核对并在提交前更新本节。

**数据更新：**首期仅接入国家税务总局、深圳市政府及相关部门的公开原文。每条政策记录首次获取与复核时间；每天检查试点来源的新通知和修订提示，发现变化后先进入待审核队列，再替换线上规则。站点不允许自动采集、结构复杂或有登录限制时，采用人工导入与双人复核。

**权限与安全：**比赛 Demo 仅用合成企业资料，采用受限访问，不公开真实企业财税文件。后续试点需取得企业授权，按最小范围收集信息，并落实加密、访问审计、撤回授权与删除机制。若以后面向公众提供生成式 AI 服务，应按实际服务形态评估适用要求；内测阶段也应保护数据安全。[个人信息保护法第六条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm) · [生成式人工智能服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)

## 7. 最小可行版本、创新点与验收

### 7.1 最小可行版本（MVP）

- **范围：**深圳企业；国家级税收政策 2 项（研发费用加计扣除、小型微利企业所得税优惠）及深圳市级公开项目通知 3—5 项。地方项目纳入可办理、已过期和不匹配样本。
- **功能：**企业画像表单、政策原文库、条件 AST 与引用校验、四态匹配、缺失事实优先提问、材料静态清单、政策版本重算、可视化审计轨迹和报告下载。
- **样本：**至少 6—8 家合成企业，形成不少于 30 个政策—企业判断组合；按政策与企业双维度分层，避免样本只靠重复改一个字段凑数。
- **演示：**现场展示一条看似匹配但被行业排除条款否定的案例，再展示政策版本变化使旧结论失效；两例都能定位到原文。
- **交付：**CodeArts 使用日志、云资源创建与部署录屏、部署手册、评测集和可视化 Demo 页面。
- **暂缓：**自动代填政府系统、真实税额自动申报、多人责任人协作、多角色权限、复杂告警、全国城市覆盖、未经授权的数据抓取。

### 7.2 可答辩的创新点

1. **表达式与引用双通道：**条件 AST 执行资格判断，独立校验器检验数值、否定词和引用片段是否一致。
2. **税收与资助双流程：**同一企业可看到不同性质的政策机会，但分别生成核算留存任务与项目申报任务。
3. **最少补充提问：**在事实缺失时优先询问最有判断价值的问题，并与固定顺序提问比较。
4. **结论时效性：**政策版本和企业事实变化触发重算，报告保留当时依据，减少旧结论传播。
5. **可审计的职责分离：**各智能体交付结构化中间结果，通过消融实验检验其必要性。
6. **可复现的“想法到应用”过程：**CodeArts、Skills、RDS、Redis、MaaS 和云端 Demo 有日志、录屏和部署手册支持。

### 7.3 验收指标（目标值，均须实测）

**数据集设计：**从 6—8 家合成企业和 5—7 项政策生成不少于 **30 个**政策—企业判断组合；额外加入政策修订、窗口关闭和冲突条款样本。按企业与政策分组划分开发集、留出集，避免同一企业模板的微调版本同时进入两组。每条样本标注到**条件级**，两名标注者独立作答；先报告 Cohen's κ，再由第三人依据原文仲裁分歧，形成共识答案。报告需说明样本规模小带来的不确定性。

| 指标 | 计算与报告方式 | 目标或门槛 |
| --- | --- | --- |
| 条件抽取 | 在留出政策上报告条件级 precision、recall、F1 | 先建立基线，再设迭代目标；不预填成绩 |
| 引用忠实度 | 人工核验每条抽取规则的原文支持关系；不足 100 条时全量检查 | 报告通过数、总数及典型错误 |
| 幻觉条款率 | 无法从原文证实的抽取条件数／总抽取条件数 | 越低越好；展示被校验器拦截的样例 |
| 硬门槛误判 | 留出集将“不满足”错判成“满足”的个数和比例 | 目标 0 例，同时给出 95% 区间与样本量，不宣称零风险 |
| 四态判断 | 与仲裁共识的一致率、混淆矩阵；并列标注者间 κ | 目标一致率 ≥90%，以实测为准 |
| 时效识别 | 已过期和版本失效样本的识别数／总数 | 目标 100%，报告分母 |
| 提问效率 | 达到同一结论时的提问数：贪心策略 vs 固定顺序 | 报告中位数及失败例 |
| 响应时间 | 已入库政策、机器自动生成报告的中位耗时；人工复核单独计时 | 机器阶段目标 ≤3 分钟 |

**消融实验：**在相同数据、模型、预算和提示词迭代次数下比较“单智能体端到端”与“职责分离 + 规则／引用校验”；报告四态判断、幻觉条款率、人工复核耗时及 token 消耗。若多智能体无明显收益，就如实缩减架构。

**外部基线与试用：**同一批样例比较人工检索、关键词搜索／通用问答与本系统的漏召回、误判、依据完整度和耗时。优先联系 **1 家代理记账机构、孵化器或产业园区**做访谈或受控试用；再争取 2—3 名实际经办人复核报告。没有真实试用时仅报告合成样本结果，不宣称企业验证。

## 9. 风险、应对与待确认事项

| 风险 | 影响 | 当前应对 |
| --- | --- | --- |
| 政策修订、附件与正文口径不一致 | 错误推荐或误导准备 | 保存版本与原文定位；修订后暂停旧结论并重新核验 |
| 大模型臆造条款或金额 | 误判资格、夸大收益 | 仅从入库原文引用；硬条件由规则引擎判定；缺证据即拒绝肯定结论 |
| 企业数据敏感 | 用户不愿录入，存在信息安全风险 | MVP 使用合成数据；真实试点最小化采集、授权、权限隔离和删除机制 |
| 涉税专业服务边界 | 输出被误当作税务意见或后续商业服务越界 | UI、报告和演示显式提示人工复核；不接受代办委托、不代签代报；正式商业服务前按实际业务模式评估《涉税专业服务管理办法（试行）》的适用义务。[国家税务总局原文](https://fgk.chinatax.gov.cn/zcfgk/c100011/c5239044/content.html) |
| 政务平台不开放接口或限制采集 | 无法自动取得数据、提交或查询真实进度 | 优先使用可用的官方开放数据／接口；遵守站点规则；必要时人工导入并双人核验；只跳转官方办理入口 |
| 云资源权限、地域或额度不匹配 | Skills 创建失败、MaaS 无法调用或产生超预算费用 | 首周做最小链路验证，记录实际服务清单与费用；失败时按手册手工创建资源，并如实展示 |
| 项目范围过大 | 初赛前难以形成可靠作品 | 固定深圳 + 2 项税收政策 + 3—5 项地方通知，优先完成评测闭环 |

**首周核对事项：**① 本校校赛节点、官方赛题附件和提交模板；② CodeArts、Skills、RDS、Redis、MaaS 在团队账号中的可用性；③ 代金券申请与服务计费范围；④ 能否联系代理记账机构或孵化器试用。赛题与报名信息从[华为 ICT 学院入口](https://e.huawei.com/cn/talent/ict-academy/)及本校通知核对。评审意见将“RDS/Redis 必选”和“总决赛开源”写作已确认要求；在未拿到可引用的官方原始附件前，本文将它们落实为**团队交付计划**，不对外宣称已经核定为硬性规则。

## 10. 预期参赛展示结构

1. **30 秒痛点：**一位中小企业财务人员同时面对国家税收政策与地方申报通知。
2. **1 分钟开发过程：**展示 CodeArts 需求拆解、Skills 配置 RDS/Redis、MaaS 接入和云端部署的真实录屏；明确人工修改处。
3. **2 分钟产品演示：**录入合成画像，先展示一条“看似匹配”的政策被行业排除条件否定；再变更政策版本，让旧结论变为“依据已失效，待复核”。两个反转均展示原文定位。
4. **1 分钟技术证据：**展示条件 AST、引用校验器、多智能体审计轨迹和 Redis 版本化缓存。
5. **1 分钟可信度：**展示条件级评测、单智能体消融、一个失败样例及涉税人工复核提示。
6. **结尾：**展示深圳试点结果与多地区复制所需的政策数据和校验机制。
