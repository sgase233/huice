## 2. 需要 M2 决定（契约与前端）

### D-1 B1b：`dateProvenance` 的响应形状（VIS-AT-04 / VIS-06）

建议（与旁表同构，去掉内部 id）：

```json
"dateProvenance": {
  "version": 1,
  "effectiveFrom": { "status": "verified", "source": "body", "locator": "第十七条", "note": null },
  "effectiveTo":   { "status": "derived", "source": null, "locator": null, "note": "有效期 5 年，5 年减 1 日" },
  "applicationWindow": { "status": "unknown", "source": null, "locator": null, "note": "年度指南未取得" }
}
```

- `status` 五值：`verified / derived / unverified / unknown / not_applicable`；
- `source` 只用 `body` / `attachment` / `null`，**不暴露 `sourceId`**；
- 旁表没有行时整个 `dateProvenance` 为 `null`（与「记录为未知」区分）；
- 只读字段，不参与 PATCH。

### D-2 契约窗口与开关（全部 E3 的发布前提）

1. `1.2.0-rc.1`（E2 DISC）并入 `openapi.yaml`；
2. `1.3.0-rc.1`：B1b + `RunStatus.interrupted` + API-12 409 + `queued` 描述修正，一次提交；
3. 同窗：`APP_VERSION` 升级、M2 重生成 `types.ts`、前端接入；

### D-3 B3 两个指标端点的契约（VIS-AT-06/07/08）

建议：

- `GET /admin/metrics/review-workload?from=&to=` → 按日 `{date, newDrafts, reviewsCompleted, pendingAtEndOfDay, availability}`；当天 `pendingAtEndOfDay=null`、`availability.dayOpen=true`；
- `GET /admin/metrics/assessment-runs?from=&to=` → 按日 `{date, total, succeeded, failed, unfinished, durationSampleCount, avgDurationMs, availability}`；缺测 `null`；
- `availability = {state: collected|partial|not_collected, coverageFrom, notes}`；
- 本版只做全局，不加 `enterpriseId` 过滤。

### D-4 B4 完整度端点的契约（VIS-AT-02）

建议：`{enterpriseId, factVersion, period, definitionVersion, groups:[{key,label,filledCount,applicableCount,ratio,items:[{factRef,status,requiredFor,evidenceRefs}]}], filledCount, applicableCount, ratio, availability}`；七状态按 `COMPLETENESS_SPEC`；`ratio=null` 表示分母为 0。

### D-5 E3a 的展示分工（VIS-AT-01/03/05）

**请 M2 定**：三条的展示规则是否如上；如需服务端补字段，说明是哪一条。

| 证据 | 覆盖标注 |
