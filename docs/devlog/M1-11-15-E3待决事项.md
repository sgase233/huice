## 1. 需要 M2 决定（契约与前端）

### D-1 B1b：`dateProvenance` 的响应形状

**问题**：VIS-06 的日期来源要进 `PolicySummary` / `PolicyDetail` / `PolicyDraft`，字段长什么样、暴露到什么粒度？

**M1 建议**（与旁表同构，去掉内部 id）：

```json
"dateProvenance": {
  "version": 1,
  "effectiveFrom": { "status": "verified", "source": "body", "locator": "第十七条", "note": null },
  "effectiveTo":   { "status": "derived", "source": null, "locator": null, "note": "有效期 5 年，5 年减 1 日" },
  "applicationWindow": { "status": "unknown", "source": null, "locator": null, "note": "年度指南未取得" }
}
```

- `status` 五值：`verified / derived / unverified / unknown / not_applicable`；
- `source`：`body` / `attachment` / `null`——**不暴露 `sourceId`**（内部 id 对前端无用，还会让人以为是可引用的来源）；
- 旁表没有行时，**整个 `dateProvenance` 为 `null`**（与「记录为未知」区分）；
- 只读字段，不参与 PATCH。

**请 M2 定**：字段名、是否包含 `note`、`null` 语义是否可接受；`types.ts` 同窗生成。
