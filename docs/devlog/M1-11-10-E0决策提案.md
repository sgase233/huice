## D1 鉴权兼容、会话实现与有效期

**结论**

1. **四类凭证，职责不重叠**

   | 凭证 | 谁在用 | 能做什么 | 绝对不能做什么 |
   | --- | --- | --- | --- |
   | 企业会话（DB） | 企业用户浏览器 | 本人企业的画像、事实、分析、报告、本人轨迹 | 读他人对象（一律 404） |
   | 审核员会话（DB） | 审核员浏览器 | 全部业务数据**只读**（含有归属 run 的轨迹）、政策管理、候选与统计 | 修改他人企业事实；读取密码、密钥、会话凭据 |
   | `ADMIN_TOKEN` Bearer | 部署脚本、curl、运维 | `/admin/**` 全部、全部 run 轨迹、自检 | 读写企业画像与事实；进入浏览器；作为前端构建变量 |
   | `huice_demo_session` | 演示入口 | **仅 `owner_user_id IS NULL` 的合成企业**，业务能力完整（可发起分析、出报告、看轨迹）、政策库只读 | 任何有主数据；`/admin/**` 写操作；`/auth/**` |

2. **凭证 × 端点矩阵（E1 后的目标行为）**

   | 端点 | 企业会话 | 审核员会话 | 运维 Bearer | demo cookie |
   | --- | --- | --- | --- | --- |
   | `GET /health` | 公开 | 公开 | 公开 | 公开 |
   | `GET /policies`、`GET /policies/{id}` | 读 | 读 | 读 | 读 |
   | `POST /enterprises` | ❌（只能由注册内建） | ❌ | ❌ | ❌ |
   | `GET /enterprises` | 本人一条 | 全部 | ❌ | 仅无主企业 |
   | `GET /enterprises/{id}` | 本人 | 全部 | ❌ | 仅无主 |
   | `PUT /enterprises/{id}/facts/{key}` | 本人 | ❌ 只读 | ❌ | 仅无主 |
   | `POST /assessment-runs` | 本人企业 | ❌ | ❌ | 仅无主企业 |
   | `GET /assessment-runs` | 本人企业 | 全部 | ❌ | 仅无主企业的 run |
   | `GET /assessment-runs/{id}`、`/report.md` | 本人 | 全部 | ❌ | 仅无主 run |
   | `GET /assessment-runs/{id}/trace` | 本人 run（脱敏投影） | **全部 run** | **全部 run** | 无主 run（演示视图） |
   | `/admin/policies/**` | ❌ | ✅ | ✅ | ❌ |
   | `/admin/discovery/**`、`/admin/metrics/**`（新增） | ❌ | ✅ | ✅ | ❌ |
   | `/auth/**` | 仅本人会话 | 同左 | ❌ | ❌ |

   审核员能读全部轨迹是负责人 2026-11-09 在 #46 的明确口径；企业侧「历史 run 无发起人则不开放」只约束企业用户，不约束审核员与运维 Bearer。

3. **会话落 DB，可撤销**
   - 表 `user_session`：`token_hash`（sha256）唯一，明文只进 Cookie，库内与日志内都不出现明文。
   - Cookie `huice_session`：`HttpOnly; Secure; SameSite=Lax; **Path=/api**`；`APP_ENV=local` 时关闭 `Secure`。选 `/api` 是因为 nginx 只代理 `/api/v1`，`/api` 覆盖且不过宽。

4. **有效期**：绝对 **12 小时**（`SESSION_TTL_HOURS`，默认 12）；空闲 **30 分钟**滑动（`SESSION_IDLE_MINUTES`，默认 30），两者取先到者。

5. **撤销时机**：登出立即写 `revoked_at`；**改密撤销该账号全部会话**；封禁/停用撤销全部会话；过期会话由定时任务清理。撤销后旧 Cookie 下一次请求即 401。

6. **CSRF**
   - 会话 Cookie 只在**已认证写请求**上校验：`X-CSRF-Token` 双提交 + Origin 同源，两者都要过。
   - **登录/注册本身不要求 CSRF token**（此时还没有可被利用的已认证状态），只校验 Origin 同源与限流。
   - **缺少 `Origin` 的请求**：携带会话 Cookie 的写请求直接拒绝（403）；带 Bearer 或不带凭证的请求不受此限制，避免打断 curl 与 CLI。

7. **限流**：登录/注册按 `IP + username` 双维度各 5 次/分钟，连续 10 次失败锁 15 分钟；Redis 不可用时降级为**进程内滑动计数并记 warning**，不阻断（uvicorn 单进程，计数够用）。

8. **角色与账号来源**
   - `enterprise` 必须绑定唯一企业；`reviewer` 企业字段可空；不设第三角色。
   - 保底管理员是预置 `reviewer`，由部署 CLI 创建，初始密码来自 `ADMIN_INITIAL_PASSWORD`（≥12 位），不进 SQL、不进仓库。
   - 审核员注册走 `REVIEWER_SIGNUP_KEY`（≥32 位、服务端环境变量、可轮换），只在服务端比对；密钥错误与普通校验失败返回同一提示。

9. **归属语义**：企业用户读/写非本人对象一律 **404**；审核员全局只读；历史 run 无发起人时企业侧入口不开放。

10. **切换期的前端影响（更正 v1）**
    - 审核页的「管理令牌」输入框必须下线，改审核员登录；`client.ts` 中对 `/admin/`、`/trace` 自动附带 Bearer 的逻辑随之删除。
    - 企业侧页面在无会话时跳登录；演示入口改用 demo cookie 走合成数据，**功能不减**。
    - 若审核页改造不能与后端同窗口完成，切换窗口内审核页应下线而不是留一个带令牌的旧页面。

**待确认（M2）**：登录页上线时间与切换窗口安排；无会话时旧前端各页的降级表现。

## D2 契约版本、部署顺序与迁移编号

**结论**

1. **版本**：E1 起用 **`1.1.0-rc.1`**，E4 前定版 `1.1.0`；每次契约变更继续走 `-rc.N`。M2 要求逐端点兼容性明确后再签收，本文件第 D1.2 节的矩阵即为该清单。
2. **兼容与失效清单（更正 v1 的「旧前端不破」）**

   | 受影响项 | v1 的错误说法 | 实际后果 | 处理 |
   | --- | --- | --- | --- |
   | 审核页「管理令牌」输入 | 声称旧前端不破 | 浏览器持令牌与新方案冲突 | E1 同窗口下线，改登录 |
   | `client.ts` 的 Bearer 自动附带 | 同上 | 同上 | 随审核页改造删除 |
   | 直接调 `/admin/**` 的浏览器脚本 | 同上 | 失效 | 改用会话或 CLI |
   | 企业侧写接口 | 同上 | 无会话不可写 | 登录后可写；demo 走合成数据 |

   **结论：E1 不是「后端加个登录、前端不动」，审核端页面必须同窗口改造。**
3. **部署顺序（固定）**：`009` 迁移 → 后端双通道（Cookie + Bearer，demo 仍放行）→ 审核页改会话登录 + 登录页 → 验收 → 再讨论是否关 demo。
4. **回滚与隔离**：不能只靠「撤销会话 + 回退旧应用」。旧应用不检查 owner，且旧 demo cookie 能列出全部企业。回滚流程固定为：
   1. 关闭外部访问（安全组收口，只留管理员内网）；
   2. 撤销新账号全部会话；
   3. **轮换 `DEMO_SESSION_SECRET` 与 `ADMIN_TOKEN`**，使所有旧凭证失效；
   4. 启动旧版本，仅用于内网读取与恢复，不对外服务；
   5. 验证旧 demo/运维入口在有主数据上无法列出或读取任何一条。
   旧应用恢复对外前，必须先确认新账号数据不可达。
5. **迁移编号**：**009 = `users_sessions_ownership`**（M1）、**010 = `policy_discovery`**（M1）；他人从 **011** 起并在 E0 表登记；开发前与每次合入前重新查最新序号，本地与云端当前均为 `008`。
6. **类型生成**：契约先评审，合入后由 M2 生成类型并接入消费者。

**待确认（M2）**：`1.1.0-rc.1` 的口径；切换窗口时长。

## D3 调度限制、抓取与候选轮换

**结论**

1. **周期**：最短 **6 小时**，默认 24 小时，可选 6/12/24/48/168；服务端回显 `limits: {minIntervalMinutes:360,maxIntervalMinutes:10080}`。
2. **唤醒**：`systemd timer` 每 **15 分钟**唤醒；CLI 读设置，未启用或未到 `next_run_at` 立即退出（退出码 0，不写运行记录）。
3. **并发与锁**：表内租约（`lock_holder` + `lock_until`，10 分钟），过期可接管并记 `stale_lock_taken`；重复启动时若同来源正在抓取则跳过本轮，不并发执行。
4. **超时与容量**：单页 15s；单次运行硬上限 30 分钟；单响应 2MB；同站间隔 ≥2s；全局并发 1；单轮最多 50 个新候选；重定向最多 5 跳且每跳复检白名单。
5. **模型预算**：单次运行 50,000 token，单候选 8,000 token；超限停止并记 `budget_exceeded`，不静默截断；`tokensUnknown` 时标记未知并停止继续消耗。**这两个数是初始值，需 M3 用首批真实页面与附件样本校准后回填。**
6. **停机补跑**：最多补跑一次最近到期任务，记录 `late_by`；不追历史周期。
7. **提交顺序（更正 v1）**
   1. 鉴权 → 2. 查 `Idempotency-Key` 与请求指纹 → 3. 命中且已成功：**直接返回原结果**，不再检查候选状态与 ETag → 4. 未命中才 `SELECT … FOR UPDATE` 锁定候选、检查 `status='pending_review'` 与 ETag、原子占用键。
   否则「提交成功但网络超时 → 重试」会因候选已 `submitted` 吃到 409。
8. **轮换事务**：取锁 → 旧候选 `expired` → 插入新 `discovery_run` → 开始抓取，前两步同一事务。运行失败时旧候选仍为 `expired`，不自动恢复。
9. **可区分的终态**（前端提示与 limits 回显的依据）

   | 状态 | 含义 |
   | --- | --- |
   | `no_new_policy` | 抓取成功、无新内容 |
   | `fetch_failed` | 来源不可达、结构变化、全部解析失败 |
   | `partial_failed` | 部分来源成功、部分失败 |
   | `budget_exceeded` | 模型预算耗尽，已停止 |
   | `oversize` | 单文件超限被跳过 |

10. **白名单**：仅 `data/policies/source_register.csv` 登记的官方域名及子域；每次重定向与最终解析 IP 复检，禁止回环、内网、链路本地与 DNS 重绑定。

**待确认（M3）**：首批网址与栏目入口样本、附件大小分布（用于校准 2MB 与预算）。

## D4 完整度数据方案

**结论**

1. **计数单位**：以 `(FactKey, 事实期间)` 为一个单位，不是「18 个键各算一格」。
2. **口径**：完整度 = 已填写的适用单位数 / 适用单位总数；`0` 与 `false` 是**已填写**；`verified=false` 不等于未填写；未知或未填不计完成；不适用不计入分母；分母为 0 时 `ratio=null`。
3. **适用性无法判断时**：字段进入 `unknownApplicability` 单列，**不计入分母**；该比例超过 30% 时，图只显示分组明细、**不显示总百分比**，并在图上注明原因。
4. **事实键全集（18）**：`region, industry, establishedDate, taxableIncome, rdExpense, rdActivity, employeeCountStart, employeeCountEnd, assetsStart, assetsEnd, revenue, equityFinancing, rdExpenseIncrease, rdExpenseRevenueRatio, rdAddDeductionClaimed, creditRecord, specificMarketSince, independentLegalEntity`。
5. **分组草案（供 M3 修订）**
   - 基础信息：`region, industry, establishedDate, independentLegalEntity, specificMarketSince, creditRecord`
   - 经营与财务：`revenue, taxableIncome, assetsStart, assetsEnd, employeeCountStart, employeeCountEnd, equityFinancing, rdExpense`
   - 研发情况：`rdActivity, rdExpenseIncrease, rdExpenseRevenueRatio, rdAddDeductionClaimed`
6. **节点级求值接口：本轮不做。** 图 1 用现有 `criteria[].expression` 展示真实结构，用 API-11 的**条款级**四态着色；子节点无结果时显式标「未提供节点结果」，不推算。
7. **实现落点**：`VIS-01` 读 `enterprise_fact`，不新增表；`definitionVersion` 在 M3 签认后写入响应。

**待确认（M3）**：分组、不适用规则、`creditRecord` 归组。

## D5 事件、快照与运行生命周期采集

**结论**

1. **审核完成事件**：以「发布成功」为唯一事件，写 `review_event(policy_version_id, review_revision, actor_kind, actor_user_id, occurred_at)`，唯一键 `(policy_version_id, review_revision)`，幂等重放不重复计数。
2. **`actor_kind`**：`user` 或 `admin_token`。用运维 Bearer 发布时 `actor_user_id` 为空但 `actor_kind='admin_token'`，事件仍可追溯——这是审核工作量趋势的分母来源，不能含糊。
3. **去重单位**：按 `policy_version`，一次发布 = 一个事件。
4. **日终待办量（更正 v1）**：不用 00:05 快照，改为**事件回放**：
   `pendingAt(T) = 截至 T 已创建 且 在 T 时点前未发布/未关闭 的 policy_version 数`
   创建时间取 `policy_version.created_at`，发布/关闭取 `review_event` 与关闭事件。该式可对任意历史时点精确重算，且与「午夜后五分钟状态变化」无关。快照表降级为**每日校验记录**（对比回放结果，不一致即告警），不再作为唯一数据源。
5. **运行生命周期**
   - `POST /assessment-runs` 先独立事务插入 `status='running'` 行：`id / enterprise_id / as_of / status / fact_version / model_or_rule_version / created_at / user_id` 在分析开始前全部已知，`finished_at` 为空。
   - 分析完成后，**结果写入与 `status='succeeded'`、`finished_at` 同一事务**；任一失败即整体回滚并置 `failed`。
   - 失败写 `error_category`；`009` 增加可空列并同步放开 `guard_assessment_run_update` 对该列的更新限制（其余列仍禁止）。
   - 中断恢复：服务启动时扫描超过运行上限仍为 `running` 的记录，置 `failed` + `error_category='interrupted'`，不伪造成成功。
6. **旧记录**：`created_at = finished_at` 的历史记录标为不可信耗时样本，查询按 `finished_at > created_at` 过滤；历史失败率不倒推。
7. **接口一致性**：`API-12/13` 遇 `failed`/`unfinished` 返回 **409 `RUN_NOT_COMPLETED`**，不得因缺 `assessments` 抛 500。
8. **模型调用趋势**：本轮不落库、不做该指标。

**待确认（M3）**：「审核完成」是否等同发布动作；`review_revision` 取值口径（版本号还是发布次数）。
