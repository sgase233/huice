## 2. 成功标准与状态规则

M2 交付应让企业用户、审核员和演示用户按各自权限完成约定流程，页面与同版契约、实际源数据一致；每项交付有明确依赖、测试结果、未覆盖范围和接收人。

状态依次使用：**待开始 → 进行中 → 待依赖/待评审 → 已实现待验收 → 已完成**。纯文档/评审任务可在完成本任务验证后标已完成；功能任务只有对应验收达标才能完成。依赖阻塞只作用于相应部分，不阻塞独立任务。

本计划创建时，下面各工作包尚未按本计划执行；此前测试、PR 评审和阶段交付只作为历史输入，不继承为当前版本的通过结论。

## 4. M2-00：基线与兼容盘点

1. 在 M2 个人分支核对工作区、基线 SHA、现行 OpenAPI 版本和前端生成类型；保留用户及其他成员未提交内容。
2. 阅读 `src/api/client.ts`、`src/api/types.ts`、`src/RealApp.tsx` 和相关页面，逐项记录请求入口、页面依赖、缓存及当前错误处理；只做本轮必要改造，不先重构整个应用。
3. 区分三种容易混淆的模式：`?mode=demo` 固定前端样例、携带服务端 demo cookie 的无主合成数据流程、未来账号会话流程。确认各自是否调用后端、如何进入/退出，不能把它们视为同一种演示模式。
4. 盘点管理令牌输入和 Bearer 自动附带、画像创建/复制、事实修改、运行/报告/轨迹读取；列明 E1 下的保留、替换、禁用及错误提示变化。
5. 核对 Node/npm、浏览器、依赖和测试配置，记录可运行范围；历史通过记录不可代替当前结果。

**交付物**：兼容清单（页面/方法与路径/当前行为/目标行为/关联 D 项/待 M1 回答的问题/验证用例），放入前端目录的任务记录或对应 PR 描述，不另建通用文档框架。

**完成标准**：账号切换影响的主要前端入口均有去向；固定样例与真实 HTTP 流程明确；没有用“接口名相同”代替字段及权限兼容分析。

## 5. M2-01：E0 交互方案与契约评审

### 5.1 可立即完成的准备

- 画清三类用户的操作步骤，列出页面、必填输入、加载/成功/失败/未完成状态、返回路径和下一步动作。优先文字流程与状态表，不新增未要求的账号后台、头像或找回密码功能。
- 企业注册需企业初始信息；审核员注册的企业信息可选方案按最终契约确认。未绑定审核员要有创建本人企业入口，查看他人企业保持只读。
- 明确刷新恢复、会话失效、改密后重新登录、重复退出、换账号、失效会话与 demo cookie 并存的界面行为；离开未保存表单时提供合理提示。
- 对候选过期、版本冲突、幂等进行中、抓取失败、无更新和预算限制列出不同提示；对图表空、未知、缺测、失效和请求错误分别设计表达。

### 5.2 草案到达后的评审步骤

1. 记录草案文件、提交 SHA、基线正式契约及范围。E1 检查 AUTH-01—07 与受影响旧接口；E2/E3 分别检查 DISC/VIS，避免将本轮不做的节点级求值重新加入。
2. 对照已有扩展设计逐项检查路径、方法、认证、对象范围、字段类型/必填/可空、枚举、分页、ETag、幂等、状态码及成功/失败示例。引用既有规则，只记录新增结论和差异。
3. 检查凭证选择与 CSRF 规则是否能由浏览器实现；登录/注册、失效会话、公开端点及退出应各有明确行为，不能让过期 cookie 阻塞重新登录且无恢复办法。
4. 对照 client 的严格响应校验、历史响应、生成类型和页面状态确认兼容性；所有待决项记录阻塞的端点和页面。
5. 独立草案先在隔离输出中验证可解析、可生成类型和示例一致性；不覆盖现行类型。依仓库实际生成工具及参数执行，不假设草案可直接替代正式契约。
6. 给出分项“接受/需修改/不影响独立工作”意见，绑定具体版本；保留 M1/M2 的确认记录。版本号和切换方式在审查后确认，不仅依据版本字符串认定兼容。

**完成标准**：本阶段使用的端点没有阻塞消费者实现的歧义；交互表与接口示例对应；有可追溯的评审结论。收到草案或 PR 合并不自动等于签收。

## 6. M2-02：原有功能回归

1. 复查画像录入、机会列表、政策详情、补问/重算、报告与材料清单、审核和轨迹的现有用例；按涉及范围执行现有单元和浏览器测试。
2. 人工核对深浅主题、窄屏、键盘路径、焦点、错误恢复和减少动态效果。自动化未覆盖的部分明确标记，模拟移动宽度不等于真机验证。
3. 对 API 失败、冲突、失效结果、无政策及字段不完整等实际风险补充有意义的断言，不为文档变更新建无关测试。
4. 真实 HTTP 专项只连接专用隔离库及合成样本；真实模型/云端联合流程需 M1 提供环境并与 M3 配合，未就绪时记录待执行。
5. 将缺陷按“阻塞核心流程/阻塞本轮扩展/可后续修复”分类，仅修本任务必要问题；发现 M1/M3 范围问题交接，不静默修改。

**完成标准**：所声明覆盖的版本、环境、用例和结果可复核；失败与跳过未写为通过；原验收遗留项继续保留，不被扩展计划覆盖。

## 7. M2-03：E1 账号、归属与会话接入

**实施前置**：E1 消费者契约签收。M1 后端未就绪时，可用符合签收契约的模拟响应验证界面；必须标明模拟，真实接入验收另记。

1. 按签收版本生成类型并接入现有 HTTP client，补 Cookie 凭据、CSRF 和统一错误处理；不用浏览器保存共享管理令牌，也不自行新增另一套身份 API。
2. 开发注册/登录、退出、改密及登录恢复。企业用户恢复本人企业；未绑定审核员可创建本人企业；审核员全局阅读入口与本人写操作明确区分。
3. 根据身份设置导航和路由守卫；服务端权限是最终依据，隐藏菜单不能替代越权校验。收到 401 提供重新登录路径，403/404 按契约显示。
4. 退出、改密或换账号时清理企业、run、报告、审核状态及未保存敏感数据；旧账号的异步响应不得覆盖新账号页面。主题偏好可独立保留。
5. 保留明确的固定样例/服务端演示入口；处理旧 demo cookie、配额耗尽和失效状态，核对画像创建、编辑、分析和报告链路。
6. 和 M1 约定维护窗口、旧审核页下线/新页启用顺序及前端回退方案。登录页完成时间只在估工及依赖明确后承诺。

**验收重点**：两个企业账号 A/B 与一个审核员完成各自流程；A 无法获取 B 的画像、报告和轨迹；审核员可查看全部轨迹但不能修改他人事实；登出/改密后的旧会话无效；刷新恢复、直接访问受限页、旧响应竞态均有验证。后端安全结论须由真实 HTTP 用例证明，模拟页面测试不能替代。

## 8. M2-04：E3a 可复用现有数据的图形

**交付物与完成标准**：每图一份源响应/样本、手算预期数字或状态、页面证据和空/未知/失效/错误用例；M3 核业务含义，M2 核呈现，缺失数据如实展示。

## 9. M2-05：E2 政策发现与候选审核

**前置**：DISC 契约签收、E1 审核员权限；真实联调需要 M1 任务与候选 API、M3 来源样本。

1. 在现有审核端内增加任务设置、运行记录和候选列表/详情，不额外建立无关管理平台；保留原手动导入入口。
2. 设置页面使用服务端 limits 校验及回显启用状态、网址和周期；区分 timer 检查与实际抓取周期，不添加契约外的立即抓取按钮。
3. 运行页按最终 schema 区分运行状态、结果原因及来源级失败，明确未到期、进行中、无更新、部分失败、预算超限和请求失败。
4. 候选详情展示来源、正文/附件定位、待核元数据、结构化条件、引用发现和重复/版本提示；允许编辑的字段以契约为准。
5. 保存使用 ETag；提交使用幂等键并正确重放。冲突和过期时刷新状态、保护仍可用的用户输入，不能盲目覆盖或重新生成键重复创建草稿。
6. 明确“提交生成待审草稿”与“发布政策”的区别；候选丢弃、抽取失败及下轮过期均有可解释的页面状态。

**完成标准**：候选未提交不出现在正式政策列表；双击、请求超时重试、过期与提交竞争、部分抓取失败、无新政策等有对应验证。事务正确性由 M1 测试及联调证明，M2 验证请求和界面不会诱发重复操作。

## 10. M2-06：E3b 完整度与趋势图

**前置**：M3 提供具体字段/期间/不适用清单及审核事件定义，M1/M2/M3 确认；对应 VIS 契约签收、真实采集或明确缺测状态可用。

1. 完整度按服务端定义展示分组、填写情况、适用依据和字段定位；不得以 `facts.length/18` 自算。存在未知适用性时不显示误导性总百分比，零分母按契约展示“不适用”。
2. 审核工作量分别显示新草稿、审核完成和日终待办；解释当前日未结算、历史部分覆盖和基线事件，不能将发布总数直接当人工审核量。
3. 运行趋势按日展示总量、成功、失败、未完成及有可信样本的耗时；无采集/部分采集/请求失败与真实零分开，不倒推历史失败率或耗时。
4. 依据接口的北京时间日期边界、coverage、availability 和样本数量展示注释；图旁保留文字或表格，颜色不是唯一信息。
5. 与 M3 使用包含午夜边界、上线基线、历史缺测、未知值和真实零的样本对账；未知字段、枚举或错误响应不静默归零。

**完成标准**：所有图值可追到源响应和业务清单；边界用例与 M3 手算一致；M1 确认数据来源，M3 复核语义，M2 页面验证留证。正式监控不使用演示随机数充数。

## 11. M2-07：E4 联合验收与发布配合

- 汇合 E1—E3 后复跑账号→画像→分析→报告，以及审核员政策发现→候选→草稿→审核发布→重新分析的约定链路；与原功能回归分开记录。
- 检查深浅主题、移动宽度、键盘、焦点、加载和恢复；列明物理移动设备和人工无障碍是否实际覆盖。
- 与 M1 核对部署代码 SHA、契约与迁移版本、前端构建及缓存策略；新旧页面切换期间不保留可误用的管理令牌界面。
- 回滚数据和基础设施由 M1 执行；M2 验证对应前端版本、登录/演示入口及错误提示，不擅自操作生产库或共享对象存储。
- 按扩展验收矩阵留证并交 M1/M3 复核。失败或缺测逐项列出；三方签收与发布决定由项目负责人组织。

## 12. 验证方法与证据要求

| 层级 | 做法 | 能证明什么 |
| --- | --- | --- |
| 文档/契约评审 | 检查链接、字段对应、示例和差异；生成工具按实际说明使用 | 文档可用、消费者设计一致；不证明接口已经实现 |
