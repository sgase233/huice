# 使用说明（M2 交接）

本文说明「惠策协同」的主要使用流程。界面文案可能随版本调整，业务规则以 [实现与接口说明](IMPLEMENTATION_AND_INTERFACE.md) 与产品口径文档为准。

## 1. 入口与角色

访问部署地址（HTTPS）。系统有三种身份：

| 身份 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| 企业用户 | 维护本企业画像、查看已发布政策、发起判断、下载报告/轨迹 | 访问后台审核、发现配置、全量统计 |
| 审核员 | 导入/抽取/审核发布政策、候选审核、查看全部运行与统计 | 修改他人企业画像、代替企业发起判断 |
| 演示访客 | `restricted` 部署下凭演示门禁 cookie 浏览公开内容；`local` 部署不提供匿名浏览，需登录 | 默认只读；写操作受演示配额与归属限制 |

**当前线上演示是 `local` 模式**：打开站点就是登录页，用发放的演示账号登录即可，不需要任何 cookie（见 §1.3）。只有切回 `restricted` 时，才需要先有 `huice_demo_session`（由运维签发，每个浏览器一次，不是每个账号一次）。

### 1.1 页面地图

| 页面 | 主要用途 |
| --- | --- |
| 首页 | 产品入口、演示入口与概览 |
| 机会列表 | 浏览已发布政策，按类型/地区/状态筛选 |
| 政策详情 | 条件、来源引文、有效期、材料清单 |
| 企业画像 | 维护事实、自动保存、删除单条事实、查看完整度 |
| 判断工作台 | 选择政策/时点发起判断，查看四态、补问与解释 |
| 报告 | 下载某次运行的 Markdown 报告 |
| 轨迹 | 查看发布链路与评估链路的脱敏步骤 |
| 后台政策 | 导入、抽取、保存条款、审核发布 |
| 政策发现 | 配置来源、查看抓取运行与候选暂存区 |
| 统计 | 审核工作量、运行趋势、资料完整度 |
| 账号抽屉 | 查看身份、修改密码、退出登录、切换主题 |

### 1.2 演示模式

- 本地/演示入口带 `?mode=demo` 时使用固定合成样例，不读写真实企业数据；
- `restricted` 部署另需演示门禁 cookie，它按浏览器生效，不与某个账号绑定；`local` 部署不需要；
- 演示数据、门禁与配额仅用于展示，不代表真实政策或企业资格。

### 1.3 演示部署：怎么进入

当前公网演示使用 `APP_ENV=local` + `DEMO_ACCESS_MODE=local`，**没有演示门禁**，也没有 demo 配额：

1. 打开 `https://<站点地址>`。证书是自签名的，浏览器会先提示不安全，点「继续前往」即可。
2. 停在登录页，用发放的演示账号登录：审核员用 `reviewer.demo`，企业侧用 `acme.alpha` / `acme.beta`。口令只走私聊渠道，不写进文档、截图或仓库。
3. 登录后按 §2（企业侧）或 §3（审核员）操作。换浏览器、换设备、清 cookie 都不影响，重新登录就行。

`local` 模式同时关闭了演示门禁与演示配额，企业注册入口对公网开放（审核员注册仍要审核员注册密钥）。比赛演示结束后应切回 `restricted`，恢复 §1.3.1 的流程。

#### 1.3.1 如切回 restricted：进入前设置演示 cookie

`DEMO_ACCESS_MODE=restricted` 下，**打开页面还不够**：所有接口（包括登录、注册）都先经过演示门禁，浏览器必须带 `huice_demo_session`。这个 cookie 按**浏览器/设备**生效，不需要每个账号登录都重设。切换方式是在 `/etc/huice/api.env` 里把 `APP_ENV` 设为 `demo`、`DEMO_ACCESS_MODE` 设为 `restricted`（两者必须成对，否则服务启动失败并只报变量名），然后重启 `huice-api`。

##### 第一步：运维签发（在 ECS 上执行）

```bash
systemd-run --pipe --wait --collect -p EnvironmentFile=/etc/huice/api.env \
  -p WorkingDirectory=/opt/huice/app \
  /opt/huice/venv/bin/python /opt/huice/app/infra/deploy/issue-session.py --hours 12
```

输出两行：

- `value:` 后面是 cookie 值；
- `Set-Cookie:` 是完整的响应头，**不要整串粘进浏览器**，只取 `value:` 那一段。

`--hours` 可改大（例如 `168` 表示 7 天）；过期时间与 `demo_quota.expires_at` 同步。签发值属于演示凭证，不要写进文档、聊天、截图或仓库。

##### 第二步：在浏览器设置（每位评委/每台设备一次）

1. 打开部署站点，例如 `https://<站点地址>`；首次会停在登录页或提示「演示入口已失效」。
2. 按 `F12` 打开开发者工具，切到 **Console**。
3. 把 `<value>` 换成第一步 `value:` 后面的内容，执行：

```js
document.cookie = "huice_demo_session=<value>; path=/; secure; samesite=lax; max-age=43200";
```

`max-age` 以秒为单位，应**不超过令牌剩余有效期**（12 小时令牌用 `43200`，7 天令牌用 `604800`）。不要把 `max-age` 设得比令牌长，否则浏览器会保留一个服务端已拒绝的值。

4. 刷新页面，或点「重新检查会话」/「进入服务端演示」。

> 也可以在 DevTools → Application → Cookies 里手工新增，但浏览器对 `HttpOnly`/`SameSite` 的编辑支持不一致；Console 写入更可靠。用 Console 写入的 cookie 不是 `HttpOnly`，不影响服务端校验。

##### 第三步：确认是否生效

在 Console 执行：

```js
fetch("/api/v1/policies", { credentials: "include" }).then(r => r.status)
```

- 返回 `200`：门禁已通过，可以继续登录或使用演示；
- 返回 `403` 且错误码 `DEMO_SESSION_REQUIRED`：cookie 没写进去、域/路径不对或已过期；
- 返回 `401` 且错误码 `DEMO_SESSION_INVALID`：cookie 值无效（常见于整串 `Set-Cookie` 被当成值）；
- 补充：`/auth/me` 对纯 demo 身份会返回 `403 ROLE_FORBIDDEN`，这是「演示身份有效但不是登录账号」的正常结果，不代表门禁失败。

##### 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面能打开，点按钮提示「演示入口已失效」 | cookie 缺失/过期 | 重新签发并按上面步骤设置 |
| 同一浏览器换账号后仍可用 | demo cookie 按浏览器生效，与账号无关 | 正常；不需要重设 |
| 换无痕窗口/换设备后失效 | 新浏览器没有 cookie | 重新设置一次 |
| 关浏览器后失效 | cookie 没有 `max-age`，是会话 cookie | 写入时加 `max-age`，且不超过令牌有效期 |
| 设置后仍 403 | 域不是站点域名、`path` 不是 `/`、或把整串 `Set-Cookie` 当成了值 | 只取 `value:`，并确认在 `https://站点` 下执行 |

##### 安全说明

- 该 cookie 只证明「演示访客」，不等于登录账号；企业数据仍按归属过滤。
- 轮换 `DEMO_SESSION_SECRET` 会让所有已签发 cookie 立即失效。
- 不要把它发到公开群聊或截图里；评委设备用完可清除。
- 本节只在 `restricted` 部署需要；`local` 部署（当前线上）跳过整节，直接登录即可。

## 2. 企业用户：从画像到判断

### 2.1 注册与登录

- 注册用户名 3—32 位，只允许小写字母、数字、`_`、`.`、`-`；提交前服务端会再规范化一次。
- 企业账号注册时同时创建企业画像，至少需要注册地 `region` 与行业 `industry`。
- 审核员账号需要审核员注册密钥；没有密钥时由运维用 `create-admin.py` 初始化。

### 2.2 维护企业画像

画像由一组「事实」组成，每条事实的键是 `(FactKey, 期起, 期止)`：

- 修改：在画像页编辑字段并保存，成功后 `factVersion`（ETag）变化。
- 自动保存：多次修改时以最后一次成功保存为准；版本冲突会提示重新加载，不会静默覆盖。
- 删除：对某条事实执行删除（接口为 `DELETE /enterprises/{id}/facts/{key}?periodStart=…&periodEnd=…`）。注册地与行业是必填键，删除画像年度的这两条会被拒绝（422 `FACT_REQUIRED`），应直接改值。
- 值留空表示「未知」，与 `0`、`false` 不同；删除表示「这条事实不存在」。

### 2.3 浏览政策

- 政策列表只展示已审核发布的版本；已过有效期/申报窗口的会标记为「已关闭」。
- 政策详情包含结构化条件、来源引文与材料清单；引文可回溯到正文或附件。
- 材料清单每项标 `facts_filled` / `facts_missing` / `manual_check` / `policy_closed`：它表示「证明材料所需事实是否齐全」，不表示材料已提交；
- 政策已关闭时材料不再要求提交，但历史详情仍可查看。

### 2.4 发起判断

选择企业、若干政策、判断时点 `asOf` 与期间，提交后同步返回结果：

| 结果 | 含义 |
| --- | --- |
| `satisfied` | 已发布条件全部满足 |
| `not_satisfied` | 至少一条硬条件不满足 |
| `insufficient_evidence` | 关键事实缺失，暂时无法下结论 |
| `conflict` | 人工审核标记了条件冲突，需人工处理 |

每条政策结果另带 `validity`：

- `current`：结论仍适用；
- `stale`：事实/政策版本在判断后发生变化，或有效期已过，需要重算。`staleReasons` 会说明是事实变化、政策换版、窗口关闭还是过期。

「首次响应」与随后读取使用同一套有效性视图：如果判断期间事实被修改/删除，POST 返回的结果就已经是 `stale`，不会先显示 `current`。

### 2.5 报告与轨迹

- 报告是 Markdown，内容来自该次运行的快照，并在开头标注「截至下载时刻」的有效性。
- 轨迹按阶段展示：发布链路（`ingestion → citation_validation → human_review`）与评估链路（`profile → retrieval → evaluation → questioning → explanation`），不包含提示词或原始资料。

## 3. 审核员：政策与运行

### 3.1 导入与审核发布

1. 导入政策：上传正文/附件与元数据，生成 `pending_parse` 草稿。
2. 抽取条件：调用模型/规则抽取，生成结构化条件草稿并做引文校验。
3. 人工修订条款：确认条件、来源引文与冲突标记。
4. 发布：发布后版本进入公开列表；同一版本重复发布会被拒绝。

已发布版本不可直接修改；需要更正时导入新版本。

### 3.2 政策发现（若启用）

- 「发现配置」里维护启用开关、抓取周期与来源网址。
- 「运行记录」区分「没有新政策」与「抓取失败」；候选先进入暂存区，人工确认元数据与条件后才提交为草稿。
- 候选不会自动变成已发布政策。
- 候选状态包括待审核、抽取失败、已提交、已丢弃、已过期；只有「提交」会生成政策草稿，丢弃/过期不会产生版本；
- 抓取失败的运行会带终态原因（如网络错误、解析失败），与「本轮没有新政策」分开显示。

### 3.3 运行列表与轨迹

审核员可查看全部企业运行，按企业筛选；未成功完成的运行不提供报告，读取结果会返回 409 `RUN_NOT_COMPLETED`。轨迹用于核对判断链路的步骤与来源。

## 4. 统计与完整度

后台「统计」页（审核员可读）包含：

### 4.1 审核工作量

- 新草稿数、审核完成数、日终待办；
- 每个指标单独标覆盖状态：`precise` / `partial` / `not_collected`；
- 未采集显示「未采集」而不是 0；当天未结算时待办显示「尚未结算」；
- 历史不可追溯的审核完成数显示为空，不按 0 处理。

### 4.2 运行趋势

- 按运行开始时间归日；成功/失败/未完成分列，`unfinished` 含运行中与中断；
- 耗时只统计有可信起止的已结束运行，无样本时显示「无可用耗时样本」；
- 采集开始前的日期只显示「已记录数」，不推断历史失败率。

### 4.3 资料完整度

- 按 `(FactKey, 期间)` 统计，状态包括：已填写、已填写（未核实）、已答未知、未填写、不适用、适用性待确认、未到期；
- 未到期单位不计入分母；分母为 0 时显示「无可统计字段」，不显示 0%；
- 人工核查条款单列，不计入完整度；
- 完整度只反映填写情况，不代表政策资格或获批概率。

## 5. 常见提示

| 提示 | 处理 |
| --- | --- |
| 会话已失效 | 重新登录；管理员改密会使全部会话失效 |
| 演示入口已失效（仅 `restricted`） | 找运维重签演示门禁 cookie，或从演示入口重新进入；`local` 部署不会出现这条 |
| 版本冲突（409） | 页面会提示重新加载；以服务端最新版本为准再提交 |
| 该版本没有条件，不能发布 | 先保存至少一条通过校验的条件 |
| 该政策已过有效期/窗口关闭 | 只能查看历史，不能再按当前状态申报 |
| 运行未完成（409） | 等运行成功后再读取；失败/中断不会生成报告 |

## 6. 数据与合规提示

- 演示环境中的企业名称均为合成数据；政策原文版权归发布机关，系统只做引文定位与演示。
- 判断结果是规则与模型辅助结论，不构成法律、税务或申报承诺；正式申报前需人工核对原文与主管部门要求。
- 完整度、指标与趋势只反映系统采集到的数据，采集缺口会在覆盖状态中标注。
