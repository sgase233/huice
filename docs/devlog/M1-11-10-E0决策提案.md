## D1 鉴权兼容、会话实现与有效期

### D1.1 四类凭证

| 凭证 | 谁在用 | 能做什么 | 绝对不能做什么 |
| --- | --- | --- | --- |
| 企业会话（DB） | 企业用户浏览器 | 本人企业的画像、事实、分析、报告、本人轨迹 | 读他人对象（一律 404） |
| 审核员会话（DB） | 审核员浏览器 | 全部业务数据**只读**（含有归属 run 的轨迹）、政策管理、候选与统计、**本人企业**的写操作与分析 | 修改他人企业事实；读取密码、密钥、会话凭据 |
| `ADMIN_TOKEN` Bearer | 部署脚本、curl、运维 | **E1 后只读**：`/admin/**` 查询、全部 run 轨迹、自检 | 任何写操作（含发布、导入、条件保存）；进入浏览器；作为前端构建变量 |
| `huice_demo_session` | 演示入口 | **仅 `owner_user_id IS NULL` 的合成企业**，业务能力完整（创建样本、发起分析、出报告、看轨迹）、政策库只读 | 任何有主数据；`/admin/**`；`/auth/**` |

**运维 Bearer 为什么降为只读**：`actor_kind='admin_token'` 只能说明「用了哪条通道」，说不了「是谁」。审核工作量趋势的分母必须可追溯到人，而运维令牌天然没有身份。E1 之后写操作一律走审核员会话；需要脚本发布时，用审核员账号登录换会话，不虚构操作者。

### D1.2 凭证 × 端点矩阵

| 端点 | 企业会话 | 审核员会话 | 运维 Bearer | demo cookie |
| --- | --- | --- | --- | --- |
| `GET /health` | 公开 | 公开 | 公开 | 公开 |
| `GET /policies`、`GET /policies/{id}` | 读 | 读 | 读 | 读 |
| `POST /enterprises` | ❌ 409（注册已内建） | ✅ 仅当尚未绑定企业 | ❌ | ✅ **强制 `owner_user_id IS NULL`** |
| `GET /enterprises` | 本人一条 | 全部 | ❌ | 仅无主企业 |
| `GET /enterprises/{id}` | 本人 | 全部 | ❌ | 仅无主 |
| `PUT /enterprises/{id}/facts/{key}` | 本人 | ❌ 他人企业只读；本人企业可写 | ❌ | 仅无主 |
| `POST /assessment-runs` | 本人企业 | 本人企业 | ❌ | 仅无主企业 |
| `GET /assessment-runs` | 本人企业 | 全部 | ❌ | 仅无主企业的 run |
| `GET /assessment-runs/{id}`、`/report.md` | 本人 | 全部 | ❌ | 仅无主 run |

| `GET /admin/metrics/**`、`/admin/discovery/**`（新增） | ❌ | ✅ | ✅ | ❌ |

### D1.3 三类入口都走通「创建/获得画像 → 编辑 → 分析 → 报告」

| 角色 | 入口 |
| --- | --- |
| 企业用户 | 注册事务内创建并绑定唯一企业（必填 `EnterpriseInput` 四要素：合成企业名、事实期间、地区、行业）；注册后维护该企业、发起分析；再调 `POST /enterprises` 返回 409 `ENTERPRISE_ALREADY_BOUND`。画像不完整时按现有补问逻辑提示，不阻塞已填事实的分析 |
| 审核员 | 首次可调 `POST /enterprises` 创建并绑定一家自己的企业（同样需完整 `EnterpriseInput`），之后与企业用户行为一致；对他人的企业保持只读 |
| 演示 | 保留 `POST /enterprises` 创建无主合成样本：服务端**强制写入 `owner_user_id = NULL`**，忽略客户端任何归属字段；单次演示会话最多 20 条；无主样本不可被认领、不可转为有主 |

「只依赖前端隐藏」的口径明确不采用：四条限制（强制 NULL、数量上限、不可认领、不可转有主）都由服务端约束与唯一索引保证。

### D1.4 会话

- `user_session`：`token_hash`（sha256）唯一；明文只进 Cookie，库内与日志内都不出现。
- Cookie `huice_session`：`HttpOnly; Secure; SameSite=Lax; Path=/api`；`APP_ENV=local` 时关闭 `Secure`。
- 有效期：绝对 **12 小时**（`SESSION_TTL_HOURS`），空闲 **30 分钟**滑动（`SESSION_IDLE_MINUTES`），先到者生效。
- 撤销：登出立即 `revoked_at`；改密撤销该账号全部会话；封禁撤销全部会话；过期会话由定时任务清理。

### D1.5 CSRF（四类请求分别定义）

| 请求类型 | Origin | CSRF token |
| --- | --- | --- |
| `POST /auth/register`、`POST /auth/login` | **必须存在且与 `PUBLIC_ORIGIN` 同源；缺失或不匹配一律 403** | 不要求（此时无已认证状态） |
| 带会话 Cookie 的其它写请求 | 必须同源 | 必须带 `X-CSRF-Token` |
| 带 demo Cookie 的写请求 | 必须同源 | 不要求；改为 Origin + Referer 同源 + 限流（demo cookie 不由用户会话派生） |
| 带 Bearer 或不带凭证（CLI/curl） | 不校验 | 不校验 |

- `csrfToken` 存会话表列，登录响应与 `GET /auth/me` 都返回**同一个值**，刷新页面后从 `/auth/me` 恢复，不做轮换（首版）。
- 上一版「无凭证请求不校验」只针对上表第四行，注册/登录属于第一行，不适用。

### D1.6 限流

- 部署确认是**单 worker**（`huice-api.service` 注释写明），进程内计数可用。
- 阈值：`IP` 维度 5 次/分钟、连续 20 次失败锁 15 分钟；`username` 维度只计数**不触发锁定**，避免他人恶意锁死某个账号。
- Redis 不可用时降级为进程内滑动窗口 + warning，不阻断；**重启清零**，接受该风险（演示期可接受，攻击面由外层 nginx `limit_req` 兜一层）。

**待确认（M2）**：登录页上线时间与切换窗口；无会话时旧前端各页的降级表现。

### D2.4 回滚与数据隔离（撤销 v2 的「收口内网即可」）

1. 回滚前用 `pg_dump` 生成只含「政策库 + `owner_user_id IS NULL` 的企业与其运行」的副本库；
2. 旧应用 `DATABASE_URL` 指向副本库，**新库保持离线**；

4. 恢复对外前，用新凭证（会话）与旧凭证（demo/Bearer）各验一遍：所有有主企业、有主 run、报告与轨迹均不可达；

## D3 调度限制、抓取与候选轮换

### D3.1 三个时钟不是一回事

| 概念 | 取值 | 说明 |
| --- | --- | --- |
| timer 唤醒间隔 | 15 分钟 | 只负责「去看一眼是否到点」，不做抓取 |
| 抓取周期 | 默认 24 小时，最短 6 小时 | 审核员在后台配置；6 小时只是下限，是否收紧由 M3 按真实来源评估 |
| 单次运行上限 | 30 分钟 | 超过即中止本轮并记 `timeout` |
| 运行互斥 | 会话级 advisory lock | **没有时间租约**，进程退出连接断开即自动释放 |

v2 的「10 分钟租约」与 30 分钟运行上限矛盾，已废弃：并发控制改用 PostgreSQL `pg_try_advisory_lock(key)`，在专用连接上持有至本轮结束；进程崩溃时连接断开，锁自动释放，不存在「租约过期但任务仍在跑」。租约概念仅保留为运行记录的审计字段，不参与并发判定。

### D3.2 抓取与容量

单页 15s；单响应 2MB；同站间隔 ≥2s；全局并发 1；单轮最多 50 个新候选；重定向最多 5 跳且每跳复检白名单。仅允许 `data/policies/source_register.csv` 登记的官方域名及子域；每次重定向与最终解析 IP 复检，禁止回环、内网、链路本地与 DNS 重绑定。

### D3.3 模型预算

单次运行 50,000 token、单候选 8,000 token，超限停止并记 `budget_exceeded`，不静默截断；`tokensUnknown` 时标记未知并停止继续消耗。**两个数是初始值，需 M3 用首批真实页面与附件实测校准后回填**；运行上限按实测确定，不与锁时长绑定。

### D3.4 停机补跑

最多补跑一次最近到期任务，记录 `late_by`；不追历史周期。

### D3.5 提交、幂等与轮换

**幂等四种返回**

| 情形 | 返回 |
| --- | --- |
| 同键 + 同请求指纹，已成功 | 返回原结果（同一 `201` 响应体） |
| 同键 + 不同请求指纹 | `409 IDEMPOTENCY_KEY_REUSED` |
| 同键，首次请求仍在进行中 | `409 IDEMPOTENCY_IN_PROGRESS`（可重试） |
| 并发首次提交，原子占用失败 | 同上 `409 IDEMPOTENCY_IN_PROGRESS` |

**执行顺序**：鉴权 → 查幂等键与指纹 → 命中已成功返回原结果（不看候选状态与 ETag）→ 未命中才 `SELECT … FOR UPDATE` 锁候选、校验 `status='pending_review'` 与 ETag、原子占用键。

**轮换事务**：`UPDATE policy_candidate SET status='expired'` 与 `INSERT INTO discovery_run` **在同一事务内提交或一起回滚**；advisory lock 在事务外持有至本轮结束。运行失败时旧候选仍为 `expired`，不自动恢复。

**可区分的终态**：`no_new_policy` / `fetch_failed` / `partial_failed` / `budget_exceeded` / `oversize` / `timeout`。

**待确认（M3）**：首批网址与栏目入口样本、附件大小分布（校准 2MB 与预算）。

## D4 完整度数据方案

1. **计数单位**：`(FactKey, 事实期间)`，不是「18 个键各算一格」。
2. **口径**：完整度 = 已填写的适用单位数 / 适用单位总数；`0` 与 `false` 是已填写；`verified=false` 不等于未填写；未知或未填不计完成；不适用不计入分母；分母为 0 时 `ratio=null`。
3. **适用性未知（撤回 v2 的 30% 阈值）**：只要存在任一 `unknownApplicability`，就**列出未知项与分组明细，不显示总百分比**。若将来要引入阈值，需 M1/M2/M3 共同确认业务含义、分母与用户提示，并写入 `definitionVersion`，不单方面设定。
4. **事实键全集（18）**：`region, industry, establishedDate, taxableIncome, rdExpense, rdActivity, employeeCountStart, employeeCountEnd, assetsStart, assetsEnd, revenue, equityFinancing, rdExpenseIncrease, rdExpenseRevenueRatio, rdAddDeductionClaimed, creditRecord, specificMarketSince, independentLegalEntity`。
5. **分组草案（供 M3 修订）**
   - 基础信息：`region, industry, establishedDate, independentLegalEntity, specificMarketSince, creditRecord`
   - 经营与财务：`revenue, taxableIncome, assetsStart, assetsEnd, employeeCountStart, employeeCountEnd, equityFinancing, rdExpense`
   - 研发情况：`rdActivity, rdExpenseIncrease, rdExpenseRevenueRatio, rdAddDeductionClaimed`
6. **节点级求值接口：本轮不做。** 图 1 用现有 `criteria[].expression` 展示真实结构，用条款级四态着色；子节点无结果时标「未提供节点结果」，不推算。
7. **实现落点**：`VIS-01` 读 `enterprise_fact`，不新增表；`definitionVersion` 在 M3 签认后写入。

**待确认（M3）**：分组、不适用规则、`creditRecord` 归组。

## D5 事件、快照与运行生命周期采集

### D5.1 审核完成事件

- `review_event(policy_version_id, review_revision, actor_kind, actor_user_id, occurred_at)`，唯一键 `(policy_version_id, review_revision)`，幂等重放不重复计数。
- `actor_kind` 取 `user` / `legacy_unknown`；**E1 后不再产生 `admin_token` 事件**（Bearer 已降为只读），历史靠 `reviewed_at` 反推的记录标 `legacy_unknown`。
- 去重单位：按 `policy_version`，一次发布 = 一个事件。

### D5.2 日终待办量

- **时间字段更正**：`policy_version` 没有 `created_at`，实际列是 **`imported_at`**。
- 状态出口只有发布：`review_status` 三态 `pending_parse / pending_review / published`，「已截止」是读取时派生、不落库。因此：
  `pendingAt(T) = count(policy_version where imported_at <= T and 不存在 <= T 的发布事件)`
- **可信起点**：`review_event` 上线时刻记为 `collectionStartedAt`。该时刻之后按事件精确回放；之前的历史用 `reviewed_at` 近似并标 `legacy`，接口返回 `availability='partial'`；无法近似（如 `reviewed_at` 为空的早期数据）返回缺测，不倒推。
- 快照表降级为**每日校验记录**（与回放比对，不一致即告警），不再是唯一数据源。

### D5.3 运行生命周期

- `POST /assessment-runs` 先独立事务插入 `status='running'`：`id / enterprise_id / as_of / status / fact_version / model_or_rule_version / created_at / user_id` 在分析开始前全部已知，`finished_at` 为空。
- `fact_version` 与事实快照在**同一读事务**（`REPEATABLE READ`）内取得，保证分析与版本标识对应同一份事实。
- 分析完成后，结果写入与 `status='succeeded'`、`finished_at` 同一事务；失败整体回滚并置 `failed`。
- `error_category` 用可空列，并放开 `guard_assessment_run_update` 对该列的更新（其余列仍禁止）。
- **中断恢复**：单 worker + advisory lock 保证同一时刻只有一个实例在跑；启动扫描仅处理 `created_at` 早于运行上限且无活动锁的 `running` 记录，置 `failed + error_category='interrupted'`，避免误标正在运行的任务。
- 旧记录 `created_at = finished_at` 标为不可信耗时样本，查询按 `finished_at > created_at` 过滤。
- `API-12/13` 遇 `failed`/`unfinished` 返回 **409 `RUN_NOT_COMPLETED`**。
- 模型调用趋势本轮不做。

**待确认（M3）**：「审核完成」是否等同发布动作；`review_revision` 取值口径。

## D6 估工、目标日与发布基线
