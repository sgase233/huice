### 待 M1 修复的问题

#### R1 / P1：restricted 会话检查可被任意非空 cookie 满足

- 位置：`services/api/app/security.py:35-42`；`infra/deploy/nginx-huice.conf` 未配置会话校验。
- 最小请求：正确管理 Bearer 下，GET `/api/v1/admin/policies` 不带 cookie 返回 403；设置 `huice_demo_session=arbitrary-not-issued-not-signed` 后返回 200。
- 影响：第二层演示访问门禁没有验证签发、完整性或过期时间。**不能绕过管理 Bearer**，无 Bearer 仍是 401，但当前不能宣称 restricted 会话有效。部署说明中“未签发 cookie 所以后台会返回 403”也不构成保护。
- 预期：在网关验证有效会话并阻止绕过网关，或后端验证签名/服务端会话与有效期；完成前保持受限部署未验收。该项至少阻塞云端演示验收，不要求把整套后续登录流程算成阶段二已完成。

#### R2 / P2：申报窗口缺少时区校验，可能返回不合契约数据或 500

- 位置：`services/api/app/schemas.py:41-43`、`services/api/app/routes/admin_policies.py:213-214`。
- 请求 A：`applicationWindow={"opensAt":"2026-10-01T09:00:00","closesAt":"2026-11-01T09:00:00"}`，其余 metadata 使用现有测试合法样本。实际 201，响应继续返回无时区时间。
- 请求 B：只将 closesAt 改为 `2026-11-01T09:00:00+08:00`，实际 500 / INTERNAL_ERROR。无时区与有时区 datetime 比较抛出 TypeError。
- 预期：按契约 Timestamp 的 date-time 要求拒绝无时区输入，返回 422 / VALIDATION_ERROR。建议使用 AwareDatetime 或等价的入口验证，并补两种边界测试。
- 复现使用 TestClient 与内存仓储，不是一次真实数据库导入。真库对无时区时间的解释尚未在本机复测，不能依赖它补救入口缺失的验证。

#### R3 / P2：未知上传字段被静默忽略，返回“成功”但丢失正文

- 位置：`services/api/app/routes/admin_policies.py:83-86`。
- 最小请求：合法 metadata，加文件 part `name="file"`（而非 `files`），内容为 `policy body`。
- 实际：201，`sources=[]`，文件没有存入对象存储或草稿。一般附加文本字段虽有测试，附加文件字段未被拒绝。
- 预期：未知 part 名或 `files` 的错误类型应返回 422 / UNEXPECTED_FIELD 或 VALIDATION_ERROR；保留契约允许的“明确不上传文件”情况，不能将字段拼错当作零文件成功。

#### R4 / P2：取得连接后的数据库断连没有转换成 503

- 位置：`services/api/app/db.py:64-75`。
- 复现：保留真实 Database.connection 和 PolicyRepository，将池替换为能成功 getconn、但 cursor 执行时抛 psycopg.OperationalError 的假池；GET `/api/v1/admin/policies` 返回 500 / INTERNAL_ERROR。
- 原因：仅在 getconn 阶段转换 OperationalError，yield 后查询/事务阶段的连接错误未经转换，落到通用 500。
- 预期：连接中断等依赖故障返回 503 / DEPENDENCY_UNAVAILABLE；SQL 编程错误仍保留 500，不笼统吞掉所有数据库异常。
- 这是故障注入复现，不是真实 RDS 断网测试。

#### R5 / P2：全新部署未创建 systemd 允许写入的对象目录

- 位置：`infra/deploy/huice-api.service:37-39`、`infra/deploy/provision.sh:44-48`、`services/api/app/integrations/obs.py:43-44`。
- 静态检查：打包步骤排除 `.local-objects`；安装脚本也没有创建它；unit 设置 ProtectSystem=strict 和 `ReadWritePaths=-/opt/huice/app/.local-objects`。该路径不存在时可写例外被忽略，服务启动后无法在只读的父目录下首次 mkdir。
- 影响：默认 OBJECT_STORE_MODE=local 的全新部署可能健康检查正常，但首次文件导入失败。mkdir 又在 OSError→503 的 try 块外，会落入 500。
- 预期：启动服务前创建目录并交给 huice 用户；如允许自定义 LOCAL_OBJECT_DIR，须同时对齐 unit 的可写目录。加入全新目录部署/首次导入验收。
- **此项仅完成静态审查；未在 ECS/systemd 环境运行复现。**
