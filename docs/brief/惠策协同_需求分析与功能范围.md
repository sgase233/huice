# 惠策协同：需求分析与功能范围

> 版本：v0.1｜日期：2026 年 10 月 19 日｜用途：华为 ICT 大赛创新赛赛题一的初赛 MVP 需求基线
>
> 依据：[项目策划案](./华为ICT大赛赛题一_政策红利挖掘与申报多智能体_初步策划案.md)及[优化意见](./评审建议_惠策协同方案_可行性与优化.md)。本文描述**拟开发功能**，不是已实现清单。正式赛题附件、校赛节点及云资源权限取得后，需要再核对交付要求。

## 1. 产品目标与用户

**产品目标：**让深圳的科技或制造业中小企业用一份基础画像发现可能适用的国家税收优惠和深圳市级资金项目，看到每个判断对应的政策条款与企业证据，并得到下一步材料准备清单。系统遇到缺失事实、矛盾条款或失效政策时，应明确停在待核实状态。

**主要用户：**企业负责人、财务人员、项目申报人员。**演示阶段的后台用户：**团队政策标注员，负责导入政策、审核机器抽取结果和维护版本。初赛演示只使用合成企业；真实企业试用另行授权和评估。

| 用户目标 | 当前工作障碍 | 产品交付 |
| --- | --- | --- |
| 找到值得核查的机会 | 国家与地方政策分散，资金项目与税收优惠混杂 | 按企业画像展示候选政策、类别、地区、有效期和官方入口 |
| 判断能否准备 | 条款分散在正文、附件、申报通知中；企业事实不完整 | 四态判断、逐条依据、缺失证据和优先补充问题 |
| 准备材料 | 不清楚需留存何种资料、何时办理 | 税收优惠与资金项目分别生成静态准备清单 |
| 避免使用旧结论 | 政策或企业情况变化后报告继续流转 | 旧结论标记失效，保留历史依据并重新核验 |

**产品定位：**企业侧政策信息整理与材料准备工具。页面和报告都必须提示：结果不构成税务专业意见，企业应在申报前由财税或项目经办人员复核。系统不承诺补贴到账，也不替企业提交申报。

## 2. 本次版本的范围决策

| 维度 | 初赛 MVP 范围 | 有余力再做 | 本阶段不做 |
| --- | --- | --- | --- |
| 地域 | 深圳市企业，国家级税收政策 + 深圳市级公开通知 | 第二个城市的规则适配验证 | 全国政策全量覆盖 |
| 政策 | 研发费用加计扣除、小型微利企业所得税优惠；3—5 项深圳市级资金项目通知 | 扩展更多政策或政策类型 | 自动保证所有政策实时完整 |
| 企业数据 | 手工录入合成画像，允许关联演示用证据片段 | 企业上传文件并抽取事实 | 未授权获取工商、税务或财务数据 |
| 判断 | 条款 AST、独立引用校验、四态判断、结论失效 | 更复杂的跨政策冲突分析 | 模型独立作出最终税务或资助资格认定 |
| 准备工作 | 静态材料清单、官方办理链接、报告导出 | 金额试算和更丰富的提醒 | 自动代填、代签、代报、政府平台进度同步 |
| 协作 | 单企业单次分析、可展示的审计轨迹 | 企业内部多人协作 | 复杂任务状态机、角色审批流 |

**MVP 的规模约束：**准备 6—8 家合成企业、5—7 项政策，形成至少 30 个政策—企业判断组合；样本应包含适用、不适用、事实不足、已过期和条款冲突。地方通知可选历史样本，但必须明确标为已关闭或仅供演示，不能呈现为当前可申报项目。

## 3. 核心业务流程与页面

```text
政策原文导入 → 条款抽取 → 引用校验 → 人工发布
                                           ↓
企业画像录入 → 候选政策 → 条件级核验 → 补充提问 → 准备清单 → 报告
                                           ↓
                           政策/企业事实变化 → 旧结论失效 → 重算
```

| 页面或视图 | 必须展示的内容 | 主要动作 |
| --- | --- | --- |
| 企业画像页 | 地区、行业、成立时间、企业规模、研发活动、事实来源与所属期间 | 新建和修改合成企业画像；提交分析 |
| 机会列表页 | 政策类别、发文机关、适用地区、版本、有效期、申报窗口、当前判断 | 筛选、进入政策详情；辨认历史通知 |
| 政策详情页 | 四态结论、条件逐条结果、所用企业事实、原文引用、缺失材料 | 查看官方原文；回答一个优先问题；重新核验 |
| 准备清单与报告页 | 税收／资金两类清单、官方入口、截止时间、风险提示、生成时间 | 下载报告；查看旧版报告 |
| 标注审核页 | 原文片段、模型抽取条件、校验失败原因、版本差异 | 修正规则、审核发布或退回 |
| 演示轨迹页 | 各智能体输入／输出摘要、规则结果、人工复核点 | 展示一次判断的可复现路径；隐藏凭据与敏感原文 |

## 4. 功能需求：初赛 MVP（P0）

以下编号用于开发任务和验收追踪。**P0** 表示初赛可运行作品所必需的范围；即便使用人工预处理或合成资料，也必须在演示中真实运行。

### FR-01 政策导入、版本与状态

- 后台可导入官方政策网页或 PDF／附件，填写标题、发文机关、文号、地区、适用主体、发布日期、有效期、申报窗口、官方 URL、获取时间和版本号。
- 同一政策的正文与附件应关联；保留原文或文件摘要，不用解读文章替代规范性原文。
- 政策状态至少区分：`待解析`、`待审核`、`已发布`、`已过期/已关闭`。未审核的规则不参与企业匹配。
- **验收：**导入一份正文与一份附件后可回看原文位置；修改政策版本后旧版仍可查看；历史申报通知在列表中显著显示关闭状态。

### FR-02 条款抽取与引用校验

- 条款解析智能体将资格条件转为结构化表达式，至少支持数值区间、日期、`AND/OR/NOT`、行业排除项和季度平均值。
- 每条条件绑定原文片段、条款或页码、政策版本；独立校验器检查数字、单位、比较方向、否定词和适用期间是否得到引用支持。
- 校验失败、原文歧义或正文附件冲突时进入人工审核；标注员可修改和发布。人工录入规则是允许的首版兜底方式。
- **验收：**将“超过 300 万元”故意误抽成“不超过 300 万元”，系统应拦截发布并显示不一致处；发布后能从判断结果跳回对应原文片段。

### FR-03 企业画像与事实证据

- 用户可填写地区、行业、成立日期、年度应纳税所得额、各季度从业人数与资产数据、研发活动及支出摘要等样本所需字段。
- 每个事实记录值、单位、所属期间、来源（用户填写／演示材料／未核实）和核验状态。未填写与数字 `0` 必须区分。
- 编辑已用于判断的事实时生成新的事实版本或哈希，并触发相关结论失效。
- **验收：**删除一个必要事实后，原“满足”不能继续显示为有效；四个季度数值可按规则形成年度季度平均值，并能回看计算输入。

### FR-04 候选检索与四态判断

- 先按地域、政策类型、适用期间等字段筛选候选，再进行文本检索；仅对**已发布**规则执行确定性求值。
- 每项政策的结果只在 `满足`、`不满足`、`证据不足`、`条款冲突` 四态中选择；“历史结论已失效”是独立标记，不混入这四态。
- 条件级结果要显示：政策条件、企业事实、事实来源、原文引用、判断理由。地区、行业、主体、日期等硬门槛为“不满足”时，不能被相似度分数覆盖。
- **验收：**行业在排除清单中的企业被判“不满足”；缺少人数数据时被判“证据不足”；矛盾条款被判“条款冲突”并显示两个出处。

### FR-05 最少补充提问

- 对“证据不足”的候选政策，按该事实能影响的候选结论数量、获取成本与敏感程度排序，一次先问一个问题，并说明提问目的。
- 用户回答后只重算依赖该事实的条件；用户可跳过，跳过不应被当作“不满足”。
- **验收：**同一案例中能展示问题排序和回答前后的结论变化；记录实际提问数，供固定顺序提问基线比较。

### FR-06 分类型准备清单

- **资金项目：**显示当期申报通知、申报窗口、材料名称、官方入口和缺失证据。关闭窗口的项目只显示历史信息，不出现“立即申报”。
- **税收优惠：**显示需要核对的条件、资料归集与留存备查事项、税务机关原文链接和财税复核提示；不套用资金拨付流程。
- **验收：**同一家合成企业同时看到一项税收优惠和一项资金项目时，两张清单的办理方式、入口和提示语不同。

### FR-07 版本失效与重新核验

- 每份判断记录政策版本、企业事实哈希、判断时间、结论有效期和所依赖事实的期间。政策规则、申报窗口、有效期或企业关键事实变化时，旧结果标为“依据已失效，待复核”。
- 历史报告与其依据保留；新旧报告分别标注生成时间和版本，不能静默覆盖。
- **验收：**修改一条演示政策的生效日期或排除条款后，相关旧结论失效，并能指出发生变化的条款；其他无关政策判断不受影响。

### FR-08 解释、报告与风险提示

- 报告包含企业画像摘要、候选政策、四态结论、逐条依据、缺口、静态准备清单、官方链接、生成时间与版本信息；支持下载可阅读文件。
- 涉税页面和报告明确显示“政策信息辅助整理；非税务专业意见；申报前请企业财税人员核对”。证据不足、冲突或过期时不得输出无条件的“符合申报条件”。
- **验收：**不查看系统内部数据库，也能从报告追溯每个结论的政策出处、企业事实和待补资料。

### FR-09 可展示的多智能体审计轨迹

- 保留采集、条款解析、企业画像、解释与准备四个角色的关键输入／输出摘要，以及规则引擎、引用校验器和人工审核结果。
- 每条轨迹关联一次判断 ID、政策版本、模型版本与运行时间；演示界面隐藏 API Key、个人信息和未授权资料。
- **验收：**从一项政策判断可顺序查看“原文 → 抽取条件 → 校验 → 事实 → 求值 → 解释”的中间结果；同一输入可重跑并解释差异。

## 5. 重要但可后移的功能（P1）

| 编号 | 功能 | 后移原因与进入条件 |
| --- | --- | --- |
| FR-10 | 企业文件上传与事实抽取 | MVP 用手工画像完成主要判断；当合成文件抽取准确率可测且云端权限明确后再加入 |
| FR-11 | 政策源自动巡检和变更通知 | MVP 可由标注员人工导入新版本；掌握来源站点接口及使用规则后再自动化 |
| FR-12 | 优惠金额试算 | 税收与财政项目计算口径不同；具备完整期间数据、可执行公式和专业复核后再开放 |
| FR-13 | 第二地区适配 | 深圳样本通过评测后，用新增地区验证规则模型的可迁移性 |
| FR-14 | 站内提醒、批量报告 | 不影响初赛核心演示；有真实用户需求后再确定提醒频率和渠道 |

**本阶段明确排除：**真实纳税申报或代理办税、政府系统自动提交、虚假证明材料生成、政务账号代登录、资助到账保证、全国全量政策采集、企业多人审批流、无授权数据抓取。若后续范围变化，应先更新合规和数据权限评估。

## 6. 数据与技术约束

| 对象 | MVP 最少字段或约束 |
| --- | --- |
| `Policy` | 标题、机关、地区、原文链接、发布日期、版本、有效期、审核状态、原文摘要 |
| `Program` | 政策类型（税收／资金）、受理窗口、官方入口、办理方式 |
| `Criterion` | 表达式 AST、适用期间、原文定位、引用校验结果、人工审核记录 |
| `EnterpriseFact` | 字段、值、单位、所属期间、证据来源、核验状态、版本 |
| `Assessment` | 企业与政策 ID、四态结论、条件级结果、政策版本、事实哈希、判断时间、结论有效期、失效状态 |
| `Trace` | 步骤名称、输入输出摘要、模型或规则版本、耗时、错误、人工处理结果 |

**拟定运行环境：**CodeArts 与 Skills 支持开发证据采集；Web 前端和 API 部署在华为云计算资源上；RDS for PostgreSQL 保存结构化数据并在实例支持时使用 pgvector；Redis 缓存解析结果及版本化判断；OBS 保存政策原文；MaaS 提供模型推理。判断缓存键包含企业、政策、政策版本和企业事实哈希，缓存不是原始证据库。模型、区域、计费和资源规格须以团队账号的首周实测为准。

**非功能要求：**

- **可追溯：**每个已发布条件与结论均有政策原文定位，失败的引用校验不得被静默跳过。
- **可重复：**同一政策版本、企业事实和规则版本应得到相同确定性判断；模型解释文本允许措辞变化，但不能改变规则结果。
- **性能：**对已入库并审核的政策，单企业机器生成初步报告的中位耗时目标不超过 3 分钟；人工复核耗时另计。
- **安全：**Demo 只用合成企业资料；凭据进入密钥配置，不进入仓库、报告或录屏；后台审核入口限制访问。
- **降级：**MaaS 限流或超预算时，已审核规则仍可进行判断，解释页面标明使用已保存结果，不伪称完成实时模型调用。
- **可用性：**页面能清楚区分四态结果、过期状态和政策类型；移动端可阅读报告属于加分项，不阻塞 MVP。

## 7. 验收场景与发布门槛

| 场景 | 预期结果 | 关联需求 |
| --- | --- | --- |
| 企业行业被政策明确排除 | 显示“不满足”，定位行业排除原文 | FR-02、FR-04 |
| 企业缺少季度人数或资产数据 | 显示“证据不足”，提出一个有理由的优先问题 | FR-03、FR-05 |
| 政策通知申报窗口已关闭 | 明显标为历史事项，不显示立即申报动作 | FR-01、FR-06 |
| 抽取器把数值比较方向写反 | 引用校验拦截，审核员可修正，未修正不得发布 | FR-02 |
| 政策版本改变 | 旧结论失效，新结论重算，历史报告可回看 | FR-07、FR-08 |
| 同一企业同时有税收与资金机会 | 两类准备清单与提示语不同 | FR-06、FR-08 |
| 模型调用失败 | 已审核规则仍可判断，页面说明解释能力降级 | FR-04、FR-08 |

**初赛发布门槛：**P0 场景全部可现场运行；至少 30 个政策—企业组合完成双人标注与仲裁；报告条件级抽取、引用忠实度、四态判断、硬门槛误判和时效识别的实测结果；完成单智能体与职责分离方案的消融对比。评测中出现错误应展示并修复，不能用预设目标代替实测结果。CodeArts 使用日志、部署录屏、源代码、部署说明和 Demo 视频作为独立交付物随赛题要求准备。

## 8. 开发依赖与待确认项

1. **官方赛题附件与本校要求：**核对 CodeArts、云资源、开源时点及提交格式；本文的功能基线可以先用合成数据开发。
2. **华为云链路：**用最小应用验证 Skills 配置 RDS／Redis、MaaS API 可用地域与额度、云端访问；若自动化创建不可用，采用可复现的手工配置并如实记录。
3. **政策样本：**冻结 2 项国家税收政策和 3—5 项深圳资金通知，保存官方原文、版本及历史窗口状态；由双人校验条件标注。
4. **用户验证：**优先接触一家代理记账机构、孵化器或园区；真实试用须另行取得授权。本阶段即使只有合成样本，也按上述范围交付。

---

**范围变更规则：**新增政策、地区或自动申报功能前，应明确负责人、数据来源、验收样本及对现有 P0 排期的影响；2026 年 11 月 15 日后原则上只修复问题和完善评测、演示材料。
