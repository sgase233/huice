# UI 设计简报（M3 起草，M2 实现）

**用户：**中小企业负责人、财务人员、项目申报人员。**首要任务：**理解“为什么匹配/不匹配、缺什么证据、下一步做什么”。

现行页面顺序：企业画像 → 机会列表 → 政策详情/证据 → 准备清单/报告；审核页与轨迹页目前仍需管理授权。2026-11-09 扩展目标：登录后按账号恢复本人企业，审核员增加候选和任务配置；本人分析轨迹须在 #46 服务端身份/归属完成后开放。范围与交付顺序见[开发计划](../DEVELOPMENT_PLAN.md)，权限、图表字段及口径见[扩展接口设计](../EXTENSION_INTERFACES.md)；下文旧线框不代表新功能已实现。

扩展界面验收约束：

- 注册说明一账号一家企业；登录、改密、退出有明确成功/失败反馈，会话过期返回登录入口。审核员“全局查看”与“本人编辑”清楚区分，菜单展示不能替代接口授权。
- 政策管理保留手动导入，另设网址/周期配置、运行记录和待审候选。候选展示原文、抓取时间、哈希、结构化条件、缺失/重复提示与过期状态；提交按钮明确为“提交为草稿”，不暗示发布完成。
- 图表复用现有业务页面，第 1—5 项及两张审核端趋势分批接入；第 6 项政策审核/版本变化图暂缓。完整度注明“仅反映填写情况，不代表资格或获批概率”；结果分布注明本次 run 与统计范围；趋势注明时区、采集覆盖和缺测。
- 所有图形保留可阅读的文字/表格替代、键盘操作及焦点，深浅主题都可辨；不只用颜色区分四态、空数据、未知、失效和错误，遵循减少动态效果设置。样例图明确标识合成数据。

设计需同时呈现四态结果与独立的“依据已失效”标记；历史窗口不得展示申报按钮。政策出处优先于装饰。下文为首版低保真线框、页面宽度、颜色/排版与移动端建议，M2 转为组件后请 M3 复核中文语义。

## 1. 全局视觉方向

| 项 | 建议 | 理由 |
| --- | --- | --- |
| 页面宽度 | 桌面最大内容宽度 1280px，正文栏 720px | 政策原文较长，控制行宽保证可读 |
| 字体 | 系统字体栈（PingFang SC / Microsoft YaHei / sans-serif）；正文 16px、辅助 14px、标题 20/24px | 中文正文不小于 14px |
| 颜色 | 中性灰为主，四态用单一强调色系；来源链接用标准蓝色下划线 | 政策内容优先，避免过多装饰色 |
| 四态配色（建议） | satisfied 绿、not_satisfied 红、insufficient_evidence 琥珀、conflict 紫；stale 一律叠加灰底「已失效」角标 | 四态与失效标记可同时读 |
| 排版密度 | 政策详情逐条条件各成一块，引用片段单独缩进 | 便于逐条回查原文 |

## 5. 完整度与趋势展示口径（2026-11-10 新增，待 M2 复核）

业务口径分别见 [COMPLETENESS_SPEC](../product/COMPLETENESS_SPEC.md) 与 [METRICS_SPEC](../product/METRICS_SPEC.md)；本节只列界面必须遵守的显示规则，不重复公式。

### 5.1 企业画像完整度

- 分组显示“基础与资质 / 经营与财务 / 研发情况 / 合规与信用”；`creditRecord` 单列时加“需动态复核”标识。
- 显示“已填写 / 适用 / 适用性待确认”三个数；**只要存在适用性待确认项，不显示总百分比**。分组也不要用百分比暗示总体已完成。
- 分母为 0 显示“不适用/当前范围没有可统计字段”，不显示 0% 或 100%。
- `0`、`false`、`verified=false` 显示为已填写；`verified=false` 另标“未核实”。`answered_unknown` 显示“已答：尚未申报/不确定”；`not_answered` 显示“未填写”；两者不合并成“缺失”。
- 季度字段（`employeeCountStart/End`、`assetsStart/End`）按四个键 × 四个季度计数，一个完整年度共 16 个单位；未来季度显示“未到期”，不入分母，并与“未填写”区分；注明“全年季度平均尚未完整”。
- 人工核查项（`manual_review` 条件、材料要求）单独成列表，不混入完整度分母。
- 图注必须含：“完整度只反映填写情况，不代表政策资格或获批概率。”

### 5.2 审核工作量与运行趋势

- 图头显示 `timeZone=Asia/Shanghai`、统计区间、`generatedAt`、覆盖状态；当天未结束标“截至 HH:mm，今日尚未结算”。
- 覆盖状态按指标分别显示：上线当天，只覆盖上线后时段的指标标“部分覆盖，自 HH:mm 起”，不把已覆盖范围内的数写成全天数；`newDrafts` 若可由历史 `imported_at` 覆盖全天，需单独说明依据，不能因此把审核完成或运行也标成全天完整。
- `null`（未采集/缺测/未结算）与 `0`（真实零）必须用不同文案和视觉表达；不得用 0 填充缺测。
- 审核完成文案建议“审核发布完成数”，并说明“以可追溯的审核员发布事件为准”；上线前历史显示“不可追溯”，不显示 0。
- 日终待办是存量，不是当天新增；候选不计入；基线日期加标记，注明“不计入审核完成”。
- 运行趋势区分成功/失败/未完成；未完成不能并进失败。耗时图显示样本数，无样本显示“无可用耗时样本”，不画 0ms。
- 历史覆盖不足时标“部分覆盖/未采集”，不画完整曲线；不展示模型调用次数/费用。
- 图形保留文字/表格替代、键盘操作、深浅主题可辨；样例图明确标“合成数据”。
