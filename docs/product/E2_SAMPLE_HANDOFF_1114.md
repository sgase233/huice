## 1. 口径与访问边界

### 1.1 判重/版本口径（按最新 #64/#66）

- **确认重复**：整页规范化文本哈希相同（同一 URL 同内容，或两个 URL 整页规范化文本完全相同）→ 计 `duplicates`，不再建候选。
- **疑似重复**：整页哈希不同、`body_fingerprint` 相同 → **两条候选都保留**；第二条 `suspectedDuplicateOf` 指向第一条；运行记录 `duplicates=0`、`suspectedDuplicates=1`。
- **同 URL 内容变化**：`content_hash` 不同即按新候选/`versionChanged` 处理，**优先于** `body_fingerprint` 判重；不得因长句指纹相同而跳过。
- **不同 URL 的不同版本**：当前代码不会仅凭正文自动把两个 URL 串成同一 `policy_id`；版本关系需人工核对/标注。S08/S09 是不同 URL/版本，不是“同 URL 内容变化”。
- **附件**：不参与判重；附件变化不会改变正文 `content_hash`/`body_fingerprint`。

- 当前同 URL 变更的预期只由代码/隔离库测试覆盖：同 URL `content_hash` 不同 → 新候选/`versionChanged`；短句截止日/金额/人数/范围变化应改变指纹；A→B→A、两个已记录 URL 同轮变同内容等为合成测试。
- **不要把 S08/S09 说成同 URL 变更，也不要把 S01/S10 说成同 URL 变更。**
- 若后续要用真实同 URL 样本，需先找到官方页面保留的修订记录/版本说明，或由站点方提供变更证据；不能用 Wayback 等第三方快照代替官方原文，也不能推测“页面曾改过”。
