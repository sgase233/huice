## 1. 状态口径与复核方法

### 1.1 五值状态

PR #69 的 `provenance` 使用以下五个状态。M3 按同一口径核对，但**不会因为“字段有值”就升级为 `verified`**：

| 状态 | 业务含义 | 判定条件 |
| --- | --- | --- |
| `verified` | 原文明确写出，且可定位到该政策版本的官方来源 | 三条同时成立：原文有明确文字；有章节/页码/段落定位；`source` 能关联到对应政策版本。缺一不可。 |
| `derived` | 不是原文直接写出的终值，而是按原文期限、生效/废止关系或替代关系推算 | 必须写 `basis`（依据条款）和 `derivedFrom`（推算起点）；页面必须显示“推算”，不得显示为已核实。 |
| `unverified` | 字段有登记值，但原文没有单列该字段，或登记值来自其他字段 | 本文中 SMART/SRDI/GREEN 的 `effective_from/effective_to` 属于此类：登记值等于申报窗口，不能当政策有效期。 |
| `unknown` | 原文未给、未取得，或本次没有可核对依据 | 不得用推算值或空白补齐；页面显示“未知/未取得”。 |
| `not_applicable` | 该政策类型不存在这个申报制字段 | 税收制度性政策、资格认定类政策没有“申报窗口”；不得伪造“立即申报”。 |

### 1.2 复核方法

- 本轮**没有重新下载全部官方原文**；以 `POLICY_SCOPE.md` 与 `POLICY_SOURCE_ATTACHMENTS_1113.md` 中已记录的 2026-11-10/11-12/11-13 命令行核查为准，并对 PR #69 的 `a82caa5` 数据文件逐条比对。
- 逐条检查：政策 ID 与版本是否对应；字段值是否与 `source_register.csv` 一致；原文是否明确；来源 URL/附件是否属于该版本；定位是否可回到原文；是否把申报窗口误当有效期；是否把 `unknown` 与 `not_applicable` 混用。
- 本文的“原文短句”只用于定位，不替代双人复核；所有政策仍为“待双人复核”。

### 1.3 时间精度、时区与区间约定

- 所有日期按 **Asia/Shanghai（UTC+8）** 的自然日理解；数据库存 UTC，展示按北京时间切日。
- 原文只写“18 时”“18:00”“20:00”，**未写时区**；M3 按北京时间处理。截止时点“18:00 整”是否包含在窗口内，原文没有给出可执行语义，**待 M1/M2 确认**；本文不把 18:00 写成已定案。
- 日期型字段按“当日 00:00:00 起”理解；终止日期是否含当日，按“有效期至某日”通常含当日处理，但 HIGHTECH/RD-SUBSIDY 的推算终点存在“满 5 年”的一日差异，不能写成已核实。
- 申报窗口的多批次、起止日期、18:00 截止、书面材料工作时间等，均以原文为准；**单一 `applicationWindow` 不能静默压平多批次**。
