## 页面信息层级与组件

`企业画像 → 机会列表 → 政策详情/证据 → 清单/报告` 是企业用户路径；真实模式包含受限审核和轨迹入口；固定样例模式的审核页仍是预览。页面顶端持续显示演示标记，左侧导航在窄屏变为横向可滚动导航。状态由文字与颜色共同表达；`StatusBadge` 分开呈现四态、失效、关闭。`EvidenceRow` 呈现合成引用，`PreparationList` 呈现按税收/资金区分的清单。

界面样本在 `src/demo.ts`，依据 OpenAPI 字段组织，刷新后恢复默认状态。样本来源链接仅指向政府网站首页，明确标为占位，不是政策条款出处。`src/api/client.ts` 是真实接口的唯一 HTTP 出口；真实模式包含企业路径、受限审核和轨迹接口调用；隔离后端阶段验收见下方记录，最终联合验收仍须留证。

## 深浅色主题开发约定

新增或修改组件时须同时适配浅色和深色主题：优先复用 `src/styles/tokens.css` 的主题变量，在 `src/styles/theme.css` 中补充必要的深色样式；文字、背景、边框、图标、焦点、禁用和状态提示都要检查。状态不能只靠颜色区分，动效应尊重系统的减少动态效果设置。提交前在两种主题及移动端检查可读性和交互。

## 第三阶段开发中（2026-10-30）

默认入口使用真实 API，`?mode=demo` 为独立固定合成演示；切换会重新载入页面。真实模式支持创建合成画像、获取候选、选择政策进行分析并查看版本化详情；真实联调和验收仍在进行，不能作为申报依据。接口不可用时显示错误，不自动退回样例。

契约 rc.3 将事实字典扩至 16 键：营业收入、新增股权融资、研发费用增量、研发费用占营业收入比重、研发费用加计扣除申报和诚信记录。金额最多两位小数；研发费用增量及应纳税所得额可为负。占比以十进制输入，例如 3% 填 `0.03`。布尔字段使用是/否/未知，诚信记录“是”表示良好；用户输入不代表已核实。占比和增量需预先计算，页面不进行资格推断。rc.4/rc.5 另增加细分市场起始日期和独立法人资格，日期事实期间须与画像期间一致，法人资格“是”表示具有独立法人资格。

代码中的 API-02/03/08—12 已有后端路由，当前联调环境和政策数据是否可用需实测；之前“后端尚未实现”仅代表当时的历史状态。rc.5 已加入比例条件引文数值和方向核对；具体条款仍需结合原文及人工复核，不应声称全部政策均已验收。补问、事实更新及重算、真实清单报告和受限后台为后续阶段。

真实模式支持 `#enterprise`、`#opportunities` 和 `#policy` 的页面导航与浏览器前进／后退；业务数据只保存在当前页面会话，刷新后不会恢复画像或分析结果。政策详情不以 URL 恢复具体政策，需从机会列表重新选择。

## 隔离后端浏览器联调

常规 `npm run test:e2e` 使用模拟接口并跳过 `live-flow.spec.ts`。真实联调用例会创建企业并 PATCH 事实，**只能指向专用隔离库**，不能对共享开发库或演示服务运行。该用例当前固定请求 `http://127.0.0.1:8000/api/v1`；Vite 也须使用该地址，CORS 必须允许 `http://127.0.0.1:5173` 并暴露 ETag。

可按以下流程在专用空库复现。先按 M1 的 `infra/local/README.md` 准备 PostgreSQL 16 + pgvector，单独创建绑定 `127.0.0.1:55432` 的测试实例及数据库 `huice_m2_phase3_test`，按顺序执行 `infra/sql/001` 至 `008`。使用 Python 3.12 安装 `services/api/requirements.lock`。不要在现有数据库执行下面的种子操作。

```powershell
# 从仓库根目录执行；<...> 替换为临时测试数据库的专用凭据
$env:HUICE_M2_TEST_DSN = 'postgresql://<用户名>:<测试密码>@127.0.0.1:55432/huice_m2_phase3_test'
<测试环境Python> -X utf8 apps/web/scripts/seed_phase3.py
  # 阶段四：在上述专用测试库追加一条合成资金政策；重复执行会拒绝。
  <测试环境Python> -X utf8 apps/web/scripts/seed_phase4_grant.py
# 用同一 URL 作为后端 DATABASE_URL，配置 local/fixture 模式和本机专用 ADMIN_TOKEN；
# 按后端说明启动 FastAPI 到 127.0.0.1:8000，再检查 health。
cd apps/web
$env:HUICE_LIVE = '1'
npm run test:e2e
Remove-Item Env:HUICE_LIVE
```

种子脚本仅接受上述回环地址、端口与专用数据库名，且要求政策表为空；它借用后端测试夹具直接标记通过并发布三条**合成政策**，故意不代表引用校验或人工审核。测试截图写入被忽略的 `test-results/`，Playwright 的后续运行会清理该目录。正式政策需由 M3 标注、双人复核并由 M1 按正式流程导入，不能用种子脚本冒充正式验收。

真实联调用例会阻止浏览器访问非 `http://127.0.0.1:8000` 的 `/api/v1/` 地址；此检查只验证地址，**不验证该端口服务实际连接哪个数据库**，运行前仍须人工确认它连接专用隔离库。测试的 Playwright API 请求也固定指向本机 8000。

## 第五阶段受限审核与轨迹（开发中）

> **历史说明：**本节及下方第五阶段复现命令记录旧 Bearer 流程，不适用于 #61/#62 后的账号会话接口。当前后台写入使用审核员会话与 CSRF，轨迹入口仅对审核员开放；同版联调见[工作计划第 20 节](M2_WORK_PLAN.md#20-e1-对接与评审答复2026-11-12)。

真实模式通过导航进入“政策审核”或“处理轨迹”，管理令牌仅保存在当前页面内存；刷新或退出后需重新输入。服务端还可能要求有效的受限演示会话。草稿支持导入、抽取、可视化条件／引用编辑、保存校验和人工确认发布；轨迹可使用当前运行或手动输入运行 UUID。页面错误显示追踪 ID，网络中断或版本冲突时先读取最新状态并人工核对，不自动重放写入。

### 第五阶段真实审核专项复现

仅使用专用隔离库，不能连接共享库或正式环境；下例使用 `huice_m2_phase5_test`，也可新建独立空库避免影响已有测试数据。先启动绑定本机的 PostgreSQL 16 + pgvector（`127.0.0.1:55432`）和 Redis（`127.0.0.1:56379`），创建专用数据库并按 `infra/sql/001` 至 `008` 顺序执行迁移。使用 Python 3.12 和 `services/api/requirements.lock` 创建测试虚拟环境；确保端口 8000 未被其他服务占用。

```powershell
# 从仓库根目录执行；凭据仅填临时测试值，不写入仓库。
$env:DATABASE_URL = 'postgresql://<用户名>:<测试密码>@127.0.0.1:55432/huice_m2_phase5_test'
$env:REDIS_URL = 'redis://127.0.0.1:56379/0'
$env:APP_ENV = 'local'
$env:MODEL_MODE = 'fixture'
$env:OBJECT_STORE_MODE = 'local'
$env:LOCAL_OBJECT_DIR = '<仓库外的测试对象目录>'
$env:ADMIN_TOKEN = '<不少于16位的临时测试令牌>'
Push-Location services/api
<测试环境Python> -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 另开终端，在 apps/web 目录：
$env:HUICE_LIVE_ADMIN = '1'
$env:HUICE_LIVE_ADMIN_TOKEN = '<与后端相同的临时测试令牌>'
npm run test:e2e -- src/tests/live-admin.spec.ts
```

执行前须核实端口 8000 的进程确实使用上述专用库。该测试会导入并发布合成政策、创建企业和分析，fixture 不是真实模型调用；旧企业路径须单独切换至上文的 `huice_m2_phase3_test`。前端 CI 仅运行构建和单元测试，Playwright 结果以单独运行记录为准。

## 云端接入交接（待联合验证）

> **历史说明：**下列旧 Bearer 部署步骤不代表 E1 当前鉴权要求；云端切换须按 `1.1.0-rc.1` 会话契约与 M1 部署说明重新核对，尚未完成联合验收。

1. M1 提供 HTTPS 前端入口、API 地址及受限演示入口。以 Node 22.x 执行 `npm ci`，将 `VITE_API_BASE_URL` 设为实际公开的 API 前缀（例如同源 `/api/v1`）后执行 `npm run build`，交付 `dist/`。该变量在构建时写入浏览器代码，只能包含公开地址，不能放令牌或密钥；地址变化后需重新构建。
2. 当前受限会话使用 `SameSite=Lax` cookie：推荐将前端与 `/api/v1` 部署在同一 HTTPS 源，并由网关转发 API。跨源但同站（同一协议和注册域名，如 `app.example.com` 与 `api.example.com`）时，须实际验证 cookie 作用域与浏览器行为；跨站页面无法仅靠 CORS 让该 cookie 随跨站 API 请求发送，请改用同源部署。跨源同站时由 M1 配置真实前端源的 `CORS_ORIGINS`，允许携带凭据、`Authorization`、`Content-Type`、`If-Match`、`Idempotency-Key`，并暴露 `ETag`、`X-Trace-Id`、`Content-Disposition`。确认网关和错误响应不剥离这些头。前端请求使用 `credentials: 'include'`，不能用通配源替代具体允许源。
3. M1 配置受限演示会话及后台 Bearer 授权，验证 HTTPS 下 cookie 的作用域、有效期和浏览器携带情况；前端令牌由授权人员在页面内输入，仅存于运行时内存，刷新或退出后需重新授权。会话签发和服务端设置见 `infra/deploy/README.md`；不要将令牌、cookie 或密钥写入前端配置、日志或验收截图。
4. 在 M1 确认的专用合成环境，以授权会话验证 401／403、强 ETag 和写冲突，再走画像、机会、分析、报告下载、审核和轨迹。核对实际模型模式及版本；fixture 只证明固定样例链路。记录实际地址、版本、结果及失败请求的脱敏追踪 ID。

以上为交接步骤，不表示云端已部署或门禁已验收；真实环境部署、M3 政策语义复核和 M1/M2 契约签收由相关负责人完成。

## 抽取用量的兼容显示

审核页支持 rc.7 的 `tokensUnknown`：为 true 时显示用量未知。DeepSeek 响应缺少该字段时可能来自 rc.6、回滚或历史重放，也可能是 rc.7 省略的已知值；页面保守显示用量状态未确认，不把数字作为已知用量。只有显式 false 才显示已知的 DeepSeek token 数；fixture/saved 无未知标记可展示零。当前没有用量合计。前端先部署、后端迁移 007 并部署 rc.7；回滚重放限制见 `contracts/README.md` 第 11 条。

## 准备清单的事实状态

真实报告按 rc.9 的 `status` 显示事实已填写、事实有缺项、需人工核对或政策已关闭；事实已填写不代表材料已提交或核验。旧响应若同时没有 `materialId` 和 `status`，显示材料状态未确认；仅缺其中一项或状态未知时拒绝该报告数据。类型由当前 OpenAPI 生成，后端部署及迁移 008 后仍需在隔离环境联合验证。
