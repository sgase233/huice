# M2 后续扩展：页面状态与验收准备

核对日期：2026-11-11。依据现行 rc.9、扩展设计及 [M3 PR #56](https://github.com/sgase233/huice/pull/56) head `985c0ffd3777d169960ae24fdfac1f4ff2112de0`。以下是待评审的前端交互和测试设计，**不是已签收 schema、已实现功能或验收结果**。PR #56 的季度单位数、上线日覆盖、午夜边界及固定 URL 能力边界已有 [M2 评审意见](https://github.com/sgase233/huice/pull/56#issuecomment-6783528878)，修订后重新对照；不把其尚有争议的样例当成最终标准。

## M2-05：政策发现与候选审核

在现有审核页面内保留手动导入；发现设置、运行记录和候选审核各自显示加载、失败、空态和下一步。真实菜单和调用须等 DISC 与 E1 契约签收。

| 页面/操作 | 展示和输入 | 结果/失败处理与需核对的契约 | 测试预期 |
| --- | --- | --- | --- |
| 设置 | 已启用状态、来源、实际抓取周期、时区、下次运行；显示服务端 limits，timer 检查不等于实际抓取 | 读取失败不复用旧 limits；保存带当前 ETag，冲突保留输入并重新读取对照；不提供契约外立即抓取 | 禁用、非法 URL/周期、过期 ETag、保存中双击、读取失败；没有写入时不声称生效 |
| 运行记录 | 计划/实际时间、来源级状态、数量、错误与预算状态，以服务端事实为准 | 未到期、运行中、无更新、部分失败、全失败、预算停止区分；未知用量不写零 | 同一来源部分失败与成功同时可见；空轮询不描述为实际抓取；网络错误不显示无更新 |
| 候选列表 | 来源、抓取时间、批次、状态、重复/版本提示与分页 | 加载失败与筛选无结果分开；过期、丢弃、已提交和抽取失败不可误作可提交 | 切换筛选清旧游标；列表为空时关联运行原因；过期状态不可发起提交 |
| 候选详情与编辑 | 正文/附件出处、定位、哈希、可空元数据、条件、引用发现；来源证据只读 | 可编辑字段、必填及结构依最终 schema；保存以 If-Match，服务端返回的新 ETag 为准 | 缺字段仍能查看；保存冲突保留输入；来源只读；引用错误和草稿可发布状态不混同 |
| 提交 | 告知“生成待审草稿，尚未发布”，先保存、再按契约携带 ETag 和稳定幂等键 | 进行中禁重复；结果未知时保留原键并先核对状态，过期/版本冲突不覆盖；丢弃按确认状态执行 | 双击一次请求；超时同键重试；过期与提交竞争只按服务端结果提示；成功可跳转关联草稿 |

**待 M1**：最终状态/错误码、limits、请求键生命周期与查询方式、过期/冲突响应、幂等进行中及状态重放示例；固定正文 URL 只能验证单篇，发现新政策还需可访问栏目或经确认的维护机制。**待 M3**：可用来源和附件/窗口样本、重复语义。事务与去重由后端/联调证明，浏览器模拟只能证明请求和页面行为。

## M2-06：完整度与趋势的显示契约

| 输入状态 | 完整度展示 | 工作量 / 运行趋势展示 | 合成验证 |
| --- | --- | --- | --- |
| 已填写且未核实 | 同时标“已填写”和“未核实”，不作为资格结论 | 不适用 | `0`、`false`、`verified=false` 仍视为已填；人工核查项单列 |
| 值为 null / 无事实行 | 分别为“已答未知”与“未填写”，若服务端能区分；均不冒充 0 | 指标为 null 显示缺测及原因 | 目标期间与相邻期间分别定位；不可用相邻年度替代 |
| 不适用 / 未到期 | 不入适用分母；注明未来季度限制，以签收清单为准 | 不适用 | 分母为 0 显示“不适用”，不显示 0% 或 100% |
| 适用性未知 | 单列未知项；不显示总百分比，提供定位 | 不适用 | 同屏有已填和未知时，显示已填/已知适用数及未知项，不能表示总体完成 |
| 已覆盖的真实零 | 展示 0，说明期间和覆盖 | 0 可绘制，文字或表格同步 | 可采集日 0 与未采集 null 并列时视觉和文字均可辨 |
| 部分覆盖 / 未采集 | 标示定义版本、范围、期间和缺口 | 按指标显示 partial / not collected，不将可读指标的覆盖套到其他指标 | 上线 10:00 后才采集的日数据标部分覆盖；非整日精确数，除非另有依据 |
| 今日未结算 | 不适用 | 今日新增/完成截至生成时刻；日终待办未结算而非 0 | 相同自然日的当前值与日终空值分开 |
| 请求错误 / 未知字段 | 给出失败及重试；未知枚举拒绝或标未识别，不默认为已填 | 保留错误提示，不画全零 | 延迟、403、500、未知 availability、空 items 分别断言 |

合成对账例：北京时间 23:55 开始、次日 00:05 结束的 run，按开始日计 1 次，可信耗时为 10 分钟；样本数为 1；未采集的日期不是零。此例只用于前端预期设计，最终取值和字段需 M1/M3 确认，不能作为实际数据或业务验收。日终边界按 `[当日 00:00, 次日 00:00)`，不截断到毫秒。

**待确认**：scope 与 definitionVersion、18 个键与每个期间的计数单位、季度计数修正、未来季度、分支适用性；审核事件定义、逐指标覆盖、历史基线与运行生命周期；对应 VIS schema 和同版样例。任何比例/事件值均由服务端提供并可对账，不用前端事实条数或随机数充数。

## M2-04：申报时间线验收样本与字段缺口（2026-11-11）

依据合并版 `58c07bd` 的 [M3 日期核查](../../docs/product/POLICY_SCOPE.md#日期可信度核查2026-11-10m3-草案)和[来源样本](../../docs/product/DISCOVERY_SOURCES.md)。下表复述 M3 命令行核查结论供对账，并非本次独立核验或双人签收；实际页面字段以将来签收的 VIS 契约和来源数据为准。

| 样本 | 预期可辨内容 | 不能据现有数据推断的内容 |
| --- | --- | --- |
| SMART 2025 | 两批网络填报与两批书面受理分别标注；如首版仅支持合并区间，须明确标注“分两批、合并区间”，并提示查看附件 | 不能把 6/13—7/7 合并窗口画成政策有效期；当前单窗口也不能表达每批时刻和书面窗口 |
| HIGHTECH 2021 | 2021-09-08 生效起点有原文依据；申报窗口显示未知；2026-09-08 终点只能标推算及依据 | 不把推算终点标为已核实；缺年度指南不推导申报时间 |
| 税收 SME 2023 | 按 M3 核查表达 2023-01-01 至 2027-12-31 有效期和自行判断办理方式 | 不为税收政策虚构申报窗口或立即申报入口 |
| 研发费税收 2023 | 起点 2023-01-01；终点说明公告未写 | 不能从 `effectiveTo=null` 直接推断永久有效，也不能把网页日期当成文日期 |
| 绿色制造 2025 | 申报截止时间来自附件，能定位来源；有效期未单列 | 不用正文缺字段推断无截止；不把申报窗口等同有效期 |

现行 rc.9 `PolicySummary/PolicyDetail` 都有必填 `effectiveFrom`、可空 `effectiveTo` 和单个可空 `applicationWindow`；后者仅有 `opensAt/closesAt`，语义为 `[opensAt, closesAt)`。它们没有日期可信度、日期来源定位、多批次及原始截止表达。缺少这些信息时，前端不能把数值本身标成已核实，也不能从 `null` 区分未知与不适用；尤其不能把半开区间的 `closesAt` 未经约定换算为原文“截止日”。VIS-06 及多窗口承载方式待 M1/M2/M3 确认后再实现。

验收需同一政策版本的源响应、字段级来源与日期状态、上述样本预期、双主题窄屏与文字替代的页面证据；M3 核业务和来源，M2 核显示，M1 核接口及数据。还需分别验证未知、推算、不适用、单窗口、多窗口、缺附件、历史版本和请求错误，不将固定合成样本当联合验收。
