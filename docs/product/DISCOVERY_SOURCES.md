## 1. 这次实际做了什么

- **日期**：2026-11-10（北京时间）。
- **方式**：命令行 `curl` GET，普通桌面浏览器 UA，30 秒超时，跟随重定向；对每个 URL 记录 HTTP 状态、`Content-Type`、下载字节数和 SHA-256。
- **范围**：`source_register.csv` 的 9 个政策正文 URL；3 组附件（智能终端 ZIP、专精特新 3 个 DOCX、绿色制造 DOC）；两个重复/辅助来源（国家税务总局 7 号公告、国务院公报）。
- **阅读深度**：
  - HTML 正文：去除标签后检索关键日期/条款；
  - 智能终端 ZIP：解压到隔离临时目录，读取附件 1 的 DOCX 文本，列出 3 个文件；
  - 绿色制造：用 `antiword` 读取 `.doc` 文本；
  - 专精特新：只读正文，3 个 DOCX 附件未逐份读取；
  - 智能终端 ZIP 的附件 2/3、PDF 未逐份读取；
  - 未做浏览器渲染、未执行 JS、未做抓取器解析、未做限速/robots 合规结论。
- **没有做**：没有绕过 403、没有登录、没有提交表单、没有高频请求；对返回 403 的栏目入口只记录，不尝试其他路径。

### 2.1 固定 URL 列表的能力边界

首版更稳妥的做法是：**M3 给出固定的正文/附件 URL 列表，M1 验证单篇抓取、附件下载与解析**。这属于**样本验证/受限方案**，必须明确：

- **能证明**：给定单篇正文/附件 URL 时，页面可访问、附件可下载（以本清单的访问日期为限），可用于验证单篇抓取、正文/附件解析、哈希判重、版本对照、日期字段等链路。
- **不能证明**：栏目列表可列取、分页/条目枚举可解析、新政策能被自动发现；也不能证明站点允许自动抓取或长期可用。
- **不能宣称**：不能因为固定 URL 都返回 200、附件都下载成功，就说“政策发现能力已达标”。固定 URL 列表只是**验证样本**，历史正文列表本身不会产生新政策候选。
- **#47 的发现能力仍待解决**：新政策发现仍需合规可访问的栏目入口、其他官方来源（如 RSS/数据开放/公报目录）或人工维护网址的机制；采用哪一种、如何排期，由项目负责人和 M1 讨论确认，并写入 E2 验收。本清单进入仓库不代表确认发现能力达标。

## 3. 可讨论的样本

### 3.1 重复内容：同一公告在两个官方站点

- S01 中国政府网：`https://www.gov.cn/zhengce/zhengceku/2023-03/28/content_5748747.htm`，200，27,618B，SHA-256 `b73e7d26…`。
- S10 国家税务总局：`https://www.chinatax.gov.cn/chinatax/n810341/n810765/c102408/202303/c5196137/content.html`，200，27,492B，SHA-256 `72804449…`。
- 两页均含“财政部 税务总局公告2023年第7号”和“自2023年1月1日起，再按照实际发生额的100%在税前加计扣除”等同一关键句；**原始 HTML 哈希不同**，因为页面框架/导航不同。
- **业务含义**：判重必须对**抽取后的正文**做规范化哈希（或正文+文号），不能对原始 HTML 做哈希；否则同一政策会被当成两条新候选。该样本可直接用于 DISC-AT-04。

### 3.2 同一政策不同版本：高企认定 2008 vs 2016

- S08 科技部 2008 版：`.../200811/t20081129_65744.html`，200，24,368B；第二十条“自2008年1月1日起实施”；已被 2016 版废止。
- S09 国务院公报 2016 版：`https://www.gov.cn/gongbao/content/2016/content_5076985.htm`，200，33,928B；第二十三条“自2016年1月1日起实施。原《高新技术企业认定管理办法》（国科发火〔2008〕172号）同时废止”。
- **业务含义**：同一 `policy_id` 的两个版本，版本变化有明文废止依据；可用于“同 URL 改内容/同政策新版本”提示与旧结论失效演示。**2008 版只能作历史版本，不得作为现行规则发布。**

### 3.3 正文与附件的信息范围不一致：智能终端

- 正文 S03（200，38,992B）只说“申报系统将在6月13日上线开放”“具体申报要求详见申报指南（附件1）”，**没有截止日期**。
- 附件 ZIP（200，2,487,736B）内附件 1 的 DOCX 明确：
  - 第一批（技术攻关/公共服务平台/爆款单品）网络填报：**2025-06-13 至 06-30 18 时**；
  - 第二批（国家配套/全屋智能载体/国产标准）网络填报：**2025-06-20 至 07-07 18 时**；
  - 书面材料受理：第一批 06-23 至 07-04，第二批 06-30 至 07-11（工作时间）。
- `source_register.csv` 目前用单一 `application_open/close = 2025-06-13/2025-07-07` 表示，这是两批网络填报的**合并区间**，不是原文的单一窗口。
- **业务含义**：
  1. 只抓正文会漏掉申报窗口；必须抓附件 1。
  2. 一个 `applicationWindow` 表达不了“两批 + 网络/书面”的多窗口；时间线图若只画一条区间，会把两批混成一条。**需 M1/M2 确认首版是否支持多窗口/分批标注**；若不支持，页面必须写明“分两批，此为合并区间”，不能静默压平。
  3. 这是“正文不含关键日期、附件才含”的典型样本，适合做候选缺失字段提示和人工核对。

### 3.4 正文与附件的信息范围不一致：绿色制造

- 正文 S05（200，36,775B）仅通知“具体要求详见申报指南”，无窗口。
- `.doc` 附件（200，95,232B）第 78 行明确：“网络填报受理时间：申报单位需于 **2024年12月21日至2025年1月6日18时**”。
- **业务含义**：窗口只在旧版 `.doc` 内；正文抽取会漏。`.doc` 是二进制旧格式，解析风险高于 DOCX/HTML；需 M1 实测转换/抽取，不能假设和 DOCX 一样。

### 3.5 失效旧链接与替代入口

- 原深科技创新规〔2021〕5号在 `stic.sz.gov.cn` 的旧 URL 本次复核返回 **404**（`https://stic.sz.gov.cn/xxgk/zcfgjjd/zcfg/szsfgfxwj/content/post_9146987.html`）。
- 现登记使用深圳政府公报版（S06，200，49,349B）。
- **业务含义**：同一政策可能换官方入口；旧 URL 不能因为“曾经登记过”就继续抓。候选/政策需要保留“原 URL → 替代 URL”的映射，避免 404 被当成“没有新政策”。

## 4. 日期识别风险（与 D4 时间线直接相关）

同一页面常有多个日期，抓错就会让时间线/失效判断出错。本次核对到的差异：

| 来源 | 成文/落款日期（政策日期） | 页面发布/信息提供日期 | 登记/使用 |
| --- | --- | --- | --- |
| S01 7 号公告 | 成文 **2023-03-26** | URL 路径 `2023-03/28` | 登记用 03-26 |
| S02 12 号公告 | 成文 **2023-08-02** | URL 路径 `202308` | 登记用 08-02 |
| S03 智能终端 | 落款 **2025-05-28** | 信息提供 **2025-05-29** | 登记用 05-28 |
| S04 专精特新 | 落款 **2025-10-13** | 信息提供 **2025-10-14** | 登记用 10-13 |
| S05 绿色制造 | 落款 **2024-11-30** | 信息提供 **2024-12-04** | 登记用 11-30 |
| S06 高企培育 | 落款 **2021-09-07** | 页面发布 **2021-09-18** | 登记用 09-07 |
| S07 研发投入补助 | 落款 **2026-02-24** | 信息提供 **2026-03-09** | 登记用 02-24 |
| S08 高企认定 2008 | 成文 **2008-04-14** | 页面发布 **2008-04-28** | 登记用 04-14 |

**建议**：
1. 抓取器分别记录 `documentDate`（成文/落款）与 `pagePublishedAt`（信息提供/页面发布），**政策时间线优先用 `documentDate`**；不要把网页日期当政策日期。
2. 若正文没有落款日期，标 `unknown`，不要用 URL 日期或抓取日期补。
3. 日期识别结果需进候选 `validationFindings`，人工核对后才能提交。
4. 税收政策没有“申报窗口”，按 `handlingMode`（自行判别、申报享受/制度性长期实施）表达，不伪造窗口；详见 [POLICY_SCOPE](POLICY_SCOPE.md) 的日期可信度核查。

## 6. 需要人工核对的内容

| 内容 | 为什么 | 建议处理 |

| 智能终端两批窗口、书面材料窗口 | 正文不含截止日，附件含多组窗口；单一窗口会误导 | 候选必须展示附件 1 原文；人工确认批次归属；时间线标“分两批” |
