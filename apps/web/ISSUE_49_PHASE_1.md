# #49 惠说惠做 · 第一阶段交互与接口草案

评审稿 v0.1 · 2026-11-26 · 本地 main 基线 `a87e889` · 正式 OpenAPI `1.4.0-rc.1`。读者为前端 M2、后端 M1 和业务复核 M3。文中“现有”指已核对仓库实现，“拟定”指本次建议，接口名称与交互仍可在评审时调整。[需求原文](https://github.com/sgase233/huice/issues/49)

## 1. 第一次交付给用户什么

用户从工作流程侧栏进入“惠说惠做”，输入一段企业情况。助手指出可填的画像字段，必要时追问。用户能看到每个建议值来自哪句话、与原值有何差异，可以修改、取消选择、整卡丢弃或确认保存。返回企业画像后能读到刚保存的值。这一流程同时适用于主动输入企业信息和输入 `@惠说惠做` 要求整理前文。

**主场景是补全已绑定的企业画像。** 普通企业账号注册时已经提交企业名称、期间、地区和行业。未绑定企业的审核员可以用同一张卡创建自己的画像。审核员从其他企业的只读详情进入时，侧栏应明确此功能的目标是“我的企业”，不得沿用当前查看对象。[注册实现](../../services/api/app/routes/auth.py) · [对象归属](../../services/api/app/access.py)

第一阶段只收文字，支持围绕画像字段的澄清。文件入口等到能处理相应格式时再展示。后续将 Word、PDF、TXT 和图片解析出的文字接入同一张草稿卡，再增加引用当前画像、分析运行与政策依据的问答。涉及“能否申报”等问题，本期提供工作台现有分析入口。画像保存成功后由用户决定是否重新分析。

## 2. 已有能力与需要补的部分

| 环节 | 当前实现 | 第一阶段的用法 |
| --- | --- | --- |
| 身份与目标 | `GET /auth/me` 返回账号和可空的 enterpriseId。账号写入沿用 cookie、Origin 与 CSRF，restricted 部署还有外层门禁 | 从当前会话确定本人企业。换账号时清空对话、草稿和迟到的响应 |
| 创建 | `POST /enterprises` 接受 EnterpriseInput，整体校验，成功返回 201、Enterprise 和 ETag。账号已绑定返回 409 ENTERPRISE_ALREADY_BOUND | 仅在未绑定分支一次性创建。企业名称、画像期间、地区码和行业码缺一项就继续补充 |
| 读取与更新 | `GET /enterprises/{id}` 返回 Enterprise 和 ETag。`PATCH /enterprises/{id}/facts/{key}` 每次按键与精确期间新增或更新一条事实 | 已绑定时锁定企业名称和画像期间。对比已选事实，顺序提交。每次成功响应中的 ETag 用于下一次请求 |
| 分析状态 | 仓储在同一事务内写事实、关联失效事件和轨迹 | 由现有写接口维护分析失效逻辑。查看分析时重新读取服务端状态 |
| 模型与材料 | 已有 fixture/DeepSeek 模型适配。现有政策导入支持文本型 PDF、UTF-8 文本，抽取目标为政策条款 | 可复用模型调用基础设施。新增“企业文字 → 字段建议”处理和输出校验。政策管理端点不适合用作企业资料入口 |
| 互动事件 | 当前正式契约没有惠说惠做聊天或画像草稿端点 | 拟增一个无画像写入的文本请求，普通 JSON 返回。确认与丢弃是前端对草稿的操作，真实写入复用上面两个接口 |

## 3. 一次实际交互

示例企业已有 2026 年画像，已填研发费用 100000.00 元。用户输入“2026 年研发费用 12 万元。营业收入我还得查一下。”助手给出“研发费用 100000.00 → 120000.00 元”，附原句，将营业收入列为待补充。用户可只保存研发费用。若用户只说“研发费用 12 万”，助手先问“这笔费用属于哪段期间？”，用户回复“2026 全年”，卡片把金额和期间分别关联到两轮输入。

| 状态 | 用户看到和能做的事 | 行为约束 |
| --- | --- | --- |
| 初次进入 | 页标题、本人企业名称或“尚未建档”、输入框、发送按钮；一个简短的合成输入示例 | 本人画像读取失败可重试。目标未确认时禁用保存 |
| 等待整理 | 保留刚发的文字，显示“正在整理企业信息” | 一次只允许一个请求。失败保留文字，用户可重试 |
| 追问 | 在对话中点明具体缺项，如期间、单位、代码或互相冲突的两句话 | 提问和回答都保留。输入单独的 @ 指令时整理本轮会话中的用户原话；没有可整理文字则提示先输入 |
| 草稿 | 卡片展示字段、期间、原值、建议值、单位、来源原句。新增项可默认选中，覆盖已有值须显式选择 | 可逐项修改、排除、展开原句。值相同项标“已一致”并跳过。信息不足项可继续补充 |
| 再次整理 | 用户可就同一段文字补充。已有未保存编辑时提示保留原卡或用新结果替换 | 仅一张可提交卡。完成或已丢弃的旧卡显示历史状态，不能再次确认 |
| 丢弃 / 提交 | “丢弃草稿”后继续聊天；“确认保存 N 项”显示实际选中数 | 丢弃不调用画像写接口。保存期间锁定卡片并逐项显示结果。离开含未存修改的页面提醒一次 |
| 结束 | 已保存项显示服务端回读值，并可“查看企业画像”；部分成功显示“已保存 1/2 项”及待处理项 | 页面刷新清空本期内存对话和草稿。已写入的事实从服务端恢复，不能把丢弃剩余草稿描述为撤销已保存事实 |

**界面与动效验收。** 在现有工作台壳内复用侧栏、主题变量和表单控件。窄屏把“原值 → 建议值”堆叠在同一字段下方。卡片入场和展开由组件状态驱动，等待真实响应时保留等待状态。错误和部分成功都有文字。发送后保留输入焦点，字段校验失败定位到对应输入。尊重减少动态效果设置。开发预览以测试响应驱动同一套组件，预览中的确认只写模拟数据；正式账号使用 HTTP。失败时保留错误，不自动切到预览。

## 4. 拟新增的整理接口

`POST /api/v1/assistant/profile-suggestions`。建议用一次请求返回一轮结果。对话和待确认草稿先保存在当前标签页内存，不引入聊天表、任务队列、流式协议或草稿 CRUD。每轮客户端发送有序的用户原话；如上一轮有追问，同时传回问题以解释“是”“2026 全年”等简短回复。后端根据会话读取本人画像，提示文本和模型返回都不能指定写入对象。

**请求示例**（下例直接要求整理前文）

```json
{
  "intent": "summarize",
  "messages": [
    {"id": "u1", "role": "user", "text": "2026 年全年的研发费用是 12 万元。"},
    {"id": "u2", "role": "user", "text": "@惠说惠做"}
  ]
}
```

| 字段 | 拟定约定 |
| --- | --- |
| intent | `message` 为普通输入或回答；独立指令或以指令开头的明确整理请求使用 `summarize`。两者都可产生草稿或追问 |
| messages | 非空有序数组，末条必须是用户输入。条目含本轮内唯一 id、role（user 或 assistant）、非空 text。assistant 只提供追问语境，引用来源严格限用户消息 |
| 容量 | 建议首版最多 20 条、每条 2,000 字、合计 12,000 字。超过则提示缩短或新开对话，避免静默截掉来源；具体上限由 M1 根据模型上下文复核 |
| 请求语义 | 仅已登录用户，沿用现有 cookie、Origin、X-CSRF-Token 和部署门禁。每次响应只作用于发起请求的会话和最新请求。重试可能再次产生模型调用，但不会保存画像 |

**200 响应示例**（字段键、单位与金额格式对齐现有画像）

```json
{
  "kind": "profile_draft",
  "text": "整理出一项研发费用，请核对金额和期间。",
  "target": {
    "enterpriseId": "11111111-1111-4111-8111-111111111111",
    "factVersion": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  },
  "profile": null,
  "items": [{
    "key": "rdExpense", "value": "120000.00", "unit": "CNY",
    "period": {"startDate": "2026-01-01", "endDate": "2026-12-31"},
    "evidence": [{"messageId": "u1", "quote": "2026 年全年的研发费用是 12 万元。"}]
  }],
  "questions": []
}
```

| 响应字段 | 前后端约定 |
| --- | --- |
| kind、text | `profile_draft` 展示一张可编辑卡。仅需追问时 `clarification`，展示 questions。请求超出本期能力时 `reply`，以 text 告知下一步 |
| target | 服务端生成的快照标识。已绑定时返回本人 enterpriseId 和 factVersion，待建档时两值均为 null。已加载画像版本与此处不一致时，先重新读取，再展示差异 |
| profile | 已绑定时为 null。新建时为 `{nameSynthetic, period, evidence}`，缺失的名称或期间用 null，原句引用格式同 items。用户可补录；绑定与资料完整性校验在提交时再执行 |
| items | 数组。每项对应现有 FactKey、FactUnit、FactValue，period 可为 null 表示待追问。可保留已确定的部分建议；字段或单位还无法判断时列入 questions。clarification/reply 时 items 为空 |
| evidence | 每条包含 messageId、quote，原句须能在对应 user 消息中逐字找到。模型给出的消息 ID、字段和原句由服务端校验，未找到依据的值退回追问。用户修改后显示“已手动修改”并保留原句供对照 |
| questions | 字符串数组，可同时随草稿返回，如“营业收入是哪一年度的？”。clarification 时至少一条；reply 时为空。用户可先提交已完整且选中的项 |
| 错误 | 沿用 `error.code/message/details/traceId` 错误体。会话失效返回 401，门禁、Origin 或 CSRF 问题按现有 403 原因处理。拟对非法请求返回 422、频率超限返回 429、上游不可用或无法产出合规结构返回 503。校验与授权在模型调用前执行 |

后端按画像事实字典校验候选，输入文字只用于提取。模型输出不能触发写操作。地区/行业文本映射为代码需要可核对的映射或用户提供代码。仅有“做制造业”不足以确定 C39。没有期间的金额也不能默认为当前年度。[字段类型](../../services/api/app/schemas.py) · [规范化逻辑](../../services/api/app/agents/profile.py)

## 5. 确认后如何写入

**已有画像。** 打开卡片时以账号、企业 ID、画像版本绑定草稿。用 `(key, period.startDate, period.endDate)` 查找原值，同键不同季度是两项。同一期间的不同候选值须先由用户选定。未提及的事实保留；“不知道”、未勾选和丢弃都不触发覆盖或删除。本期不通过聊天清空已知值。新增相同事实与更新相同事实都走现有 PATCH。

例如用户选中上述研发费用后，向 `PATCH /api/v1/enterprises/11111111-1111-4111-8111-111111111111/facts/rdExpense` 发送下列 JSON。携带会话 CSRF 和从 GET 或前一个成功写响应原样取得的带引号强 ETag 作为 `If-Match`。

```json
{
  "value": "120000.00", "unit": "CNY",
  "period": {"startDate": "2026-01-01", "endDate": "2026-12-31"},
  "source": "user_input"
}
```

按用户确认时的固定顺序逐条发送。每次成功接收完整 Enterprise 与新 ETag，再发送下一条。第一条失败即停止，其余显示“尚未提交”。PATCH 的成功边界是单条事实。若产品决定多项必须全部成功或全部回滚，M1 应另拟单事务批量接口，前端不能用多次 PATCH 承诺原子性。

**待建画像。** 用户确认名称、画像期间和必填事实后仅发一次 `POST /api/v1/enterprises`。下例是最小有效请求，可在 facts 追加已选定的研发费用。201 后用响应绑定企业，打开画像时回读。新建后的可写对象仍由服务端判断。

```json
{
  "nameSynthetic": "合成企业甲",
  "period": {"startDate": "2026-01-01", "endDate": "2026-12-31"},
  "facts": [
    {"key": "region", "value": "440300", "unit": "code", "period": {"startDate": "2026-01-01", "endDate": "2026-12-31"}, "source": "user_input"},
    {"key": "industry", "value": "C39", "unit": "code", "period": {"startDate": "2026-01-01", "endDate": "2026-12-31"}, "source": "user_input"}
  ]
}
```

**字段口径。** 18 个可用键和 6 类单位以代码字典为准。地区、行业、成立日期、细分市场起始日期必须挂在画像期间。新建时地区、行业各须一个非空值。金额用十进制字符串，12 万元写为 `"120000.00"`，3% 写为 `"0.03"`，布尔用 JSON 的 true/false。零、未知和未提及分别处理。用户确认仅表示同意录入；文字录入使用 `user_input`，公开写入的 verified 由服务端确定为 false。草稿中的 quote、messageId、修改痕迹只在本轮对照，不传入现有 FactInput。[字段字典](../../services/api/app/domain/rules.py) · [写入模型](../../services/api/app/schemas.py)

| 异常 | 页面恢复步骤 |
| --- | --- |
| 409 VERSION_CONFLICT | 停止剩余写入，GET 最新画像，展示旧值、现值、拟写值。保留编辑，由用户重新确认仍要写的项；不拿新 ETag 自动覆盖 |
| 写请求超时 / 断网 | 标“保存结果待核对”。PATCH 先 GET 对比具体事实和期间。若已一致标“当前画像已是此值”，其余差异重新确认。POST 先读 /auth/me，已绑定则读本人画像核对；确认仍未绑定后才允许手动重试 |
| 409 ENTERPRISE_ALREADY_BOUND | 更新本人会话与画像，切换到已有画像的差异卡，重新确认。不会因为收到冲突就直接修改现有企业 |
| 422 / 400 INVALID_IF_MATCH / 428 MISSING_IF_MATCH | 422 把 fieldErrors 对应到字段，保留编辑。版本头问题重新读取完整 ETag，核对版本后再允许确认 |
| 返回 401、目标不可访问或换账号 | 失效会话走现有登录恢复；目标不可访问时停止提交。旧账号文本、草稿与迟到响应不能显示在下一账号中 |

## 6. 前后端如何对照验收

M2 先固定以下输入、响应和界面状态，使用现有 Playwright 请求拦截或本地开发预览。正式页面与预览复用同一聊天列表、草稿卡、提交状态和 CSS。M1 先以 fixture 实现同一请求和响应，再接模型并验证抽取质量。视觉验收对比同一字段、状态和视口；联网延迟可变，测试等待实际状态切换。

| 场景 | 可观察的通过条件 |
| --- | --- |
| 文本完整 / 普通输入与 @ | 两种入口都产生可编辑卡。金额和期间规范化正确，点击来源能定位原话；确认前画像写请求数为零 |
| 缺年度 / 两句矛盾 / 无依据 | 助手针对缺口追问。补充后可整理；没有依据的字段不能作为已确定值提交 |
| 编辑、丢弃和未知 | 修改 12 万为 10 万后只提交用户选定的 10 万。丢弃整卡后重新读取画像，与操作前一致。未知不能覆盖为零 |
| 已有与未绑定账号 | 普通企业走 PATCH；未绑定审核员可走 POST。创建缺地区或行业时提示补充，补齐后 201；审核员浏览其他企业时不能写入对方画像 |
| 多项、并发、重复点击 | 两项保存的第二个请求使用第一个响应的 ETag；同一点击处理中不能再次发请求。制造第二项冲突，第一项保留且可回读，第二项仍可编辑 |
| 请求已提交但响应丢失 | 页面支持先回读再确认。重试不重复建企、不重复提交已一致项。切换账号后旧请求返回不能改变界面 |
| 模型异常 / 旧分析 | 未取得合法模型结果时显示失败或追问。真实保存后按现有规则回读受影响运行的有效性，聊天本身不创建分析运行 |
| 视觉与键盘 | 375px 和桌面、深浅主题下均能编辑和确认；键盘能定位错误与原句，减少动态效果时不依赖动画完成操作 |

**建议评审顺序。** 产品先确认“已有画像优先、逐条保存可部分成功、草稿刷新即清空”这三个用户可见选择。M3 确认单位换算、期间、来源和矛盾样例。M1/M2 用一组成功、追问和失败响应走读接口，再由 M1 确认请求上限、模型用量和错误码并纳入正式契约。M2 据此冻结预览状态。最终联调在隔离环境核对真实账号、保存后的画像与运行状态，另用合成文本单独验证真实模型的抽取结果。
